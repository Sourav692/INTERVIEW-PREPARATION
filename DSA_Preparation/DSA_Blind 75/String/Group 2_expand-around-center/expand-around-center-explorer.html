The core flip

Every palindrome is symmetric around a middle — either a single character (odd length) or the gap between two characters (even length). There are ~2n possible centers. Plant a pointer pair at each one and walk outward while both sides match; the longest successful expansion wins.

Why 2n centers, not n? A center can be a single character ("aba" centered on b) or a gap between two characters ("aa" centered between the two a's). Checking only single-character centers would silently miss every even-length palindrome.

Optimal Solution — Expand Around Center · O(n²) time, O(1) space

def longest_palindrome(s: str) -> str:
    if not s:
        return ""
    start, end = 0, 0
    def grow(l, r):
        while l >= 0 and r < len(s) and s[l] == s[r]:
            l -= 1; r += 1
        return l + 1, r - 1              # step back to the last valid bounds
    for i in range(len(s)):
        l1, r1 = grow(i, i)              # odd-length, centered ON i
        l2, r2 = grow(i, i + 1)          # even-length, centered BETWEEN i and i+1
        if r1 - l1 > end - start:
            start, end = l1, r1
        if r2 - l2 > end - start:
            start, end = l2, r2
    return s[start:end + 1]

~2n centers, each can expand up to n steps → O(n²) time. Only pointers and bounds tracked → O(1) space (versus O(n²) for the DP-table alternative).

The core flip

Same engine as Longest Palindromic Substring — but instead of tracking the single longest expansion, every successful outward step is one more palindrome to count. Counting is a natural by-product of the same expansion loop.

Why this can't double-count: each palindromic substring has exactly one center and one radius — "aa" at positions [0,1] is only ever discovered by the even-center expansion starting between index 0 and 1, never by any odd-center expansion. Every distinct (center, radius) pair is a distinct substring.

Optimal Solution — Expand Around Center, Count Successes · O(n²) time, O(1) space

def count_substrings(s: str) -> int:
    n = len(s)
    def grow(l, r):
        cnt = 0
        while l >= 0 and r < n and s[l] == s[r]:
            cnt += 1                      # each successful step = one more palindrome
            l -= 1; r += 1
        return cnt
    total = 0
    for i in range(n):
        total += grow(i, i)               # odd-length, centered on i
        total += grow(i, i + 1)           # even-length, centered between i and i+1
    return total

Same shape as Longest Palindromic Substring → O(n²) time, O(1) space. Counting instead of comparing lengths is the only change.
