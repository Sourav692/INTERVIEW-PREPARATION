The core flip

Fix one number a as an anchor — the rest becomes a classic 2-Sum for target -a. On a sorted array, two pointers (lo, hi) find every pair summing to -a in one linear sweep, turning the O(n³) triple loop into O(n²). Sortedness also makes duplicate-skipping trivial — just skip equal neighbors.

Why sort first? Sorting (O(n log n)) does double duty: it enables the two-pointer sweep (sum too small → move lo right; too big → move hi left) and makes de-duplication a simple "skip equal neighbors" step — both for the anchor and for lo/hi after a hit.

Optimal Solution — Sort + Two Pointers · O(n²) time, O(1) extra space

def three_sum(nums: list[int]) -> list[list[int]]:
    nums = sorted(nums)              # enables two pointers + easy dedup
    n = len(nums)
    res = []
    for i in range(n - 2):           # fix the anchor (smallest of the triple)
        if nums[i] > 0:
            break                    # smallest is positive -> can't reach 0
        if i > 0 and nums[i] == nums[i - 1]:
            continue                 # skip duplicate anchors
        lo, hi = i + 1, n - 1
        while lo < hi:
            s = nums[i] + nums[lo] + nums[hi]
            if s < 0:
                lo += 1               # sum too small -> need a bigger value
            elif s > 0:
                hi -= 1               # sum too big -> need a smaller value
            else:
                res.append([nums[i], nums[lo], nums[hi]])
                lo += 1; hi -= 1
                while lo < hi and nums[lo] == nums[lo - 1]:
                    lo += 1           # skip duplicate seconds
                while lo < hi and nums[hi] == nums[hi + 1]:
                    hi -= 1           # skip duplicate thirds
    return res

Anchor loop is O(n); each anchor's two-pointer sweep is O(n) → O(n²) total (sort adds O(n log n), dominated by the n² term). Only pointers used beyond output → O(1) extra space.

The core flip

Water held between walls i and j is min(height[i], height[j]) × (j - i) — capped by the shorter wall. Start at the widest possible container (both ends). As width can only shrink from here, the only move that could ever increase area is raising the shorter wall — moving the taller one can never help, since width shrinks either way and height stays capped by the same short wall or gets worse.

Greedy proof sketch: the container is bounded by its shorter wall. Keeping that shorter wall and shrinking the width can only decrease area — so no better container uses that wall at this width again. It's provably safe to discard it and move inward.

Optimal Solution — Two Pointers · O(n) time, O(1) space

def max_area(height: list[int]) -> int:
    lo, hi = 0, len(height) - 1      # start with the two widest walls
    best = 0
    while lo < hi:
        area = min(height[lo], height[hi]) * (hi - lo)
        best = max(best, area)
        if height[lo] < height[hi]:  # move the SHORTER wall inward...
            lo += 1                  # ...only move that can improve area
        else:
            hi -= 1
    return best

Single pass, pointers only move inward → each index visited once → O(n) time. Two integer pointers → O(1) space.
