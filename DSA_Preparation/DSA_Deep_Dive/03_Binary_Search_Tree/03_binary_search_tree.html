🔍 Binary Search Trees

One ordering rule → O(log n) search, insert, delete, and a free sort.

searchin-orderinsertdeletevalidatebalance

The one rule (the BST invariant)

For every node: everything in its left subtree is smaller, everything in its right subtree is larger — recursively.

The payoff: at each node you discard half the tree — binary search on a tree, so search / insert / delete are O(h) (O(log n) when balanced).

① Search — follow the comparisons

Equal → found; smaller → go left; larger → go right. Each step drops the other half.

② In-order walk → sorted output

Because left < node < right everywhere, an in-order traversal visits values in ascending order — a free sort.

output (sorted!)

③ Insert — search, then hang the new node

Walk down as if searching; the empty slot you land on is exactly where the value belongs.

④ Delete — the three cases

0 children → remove. 1 child → splice. 2 children → replace with the in-order successor (smallest in the right subtree), then delete that.

⑤ Validate — carry a (low, high) range

The trap: checking only immediate children is wrong. Each node must fit an allowed range that tightens as you descend.

⑥ Why balance is everything

Sorted inserts make a skewed tree (a linked list) → O(n). A balanced tree stays O(log n).
