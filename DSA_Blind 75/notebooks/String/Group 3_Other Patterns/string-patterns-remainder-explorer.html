The core flip — compare recipes, not letters

Two words are anagrams iff they use the exact same letters the same number of times. Instead of comparing the words directly, tally each letter's count from s, then "spend" one from that tally for each letter of t. If anything is left over — or t needs a letter s never had — they don't match.

Why check length first: different lengths can never be anagrams — checking upfront avoids wasted work and handles an edge case the counting loop alone wouldn't catch cleanly.

Optimal Solution — Letter Counting · O(n) time, O(1) space

def is_anagram(s: str, t: str) -> bool:
    if len(s) != len(t):
        return False
    count = {}
    for c in s:
        count[c] = count.get(c, 0) + 1
    for c in t:
        if c not in count:
            return False
        count[c] -= 1
        if count[c] == 0:
            del count[c]
    return len(count) == 0

Two linear passes → O(n) time. Count map bounded by the alphabet (26 lowercase letters) → O(1) space.

The core flip — fingerprint, then bucket

Turn each word into a canonical form that every anagram shares — its sorted letters — then group words by that fingerprint in a hash map. Anagrams collide into the same bucket automatically.

["eat","tea","tan","ate","nat","bat"]
Press "Step" to begin. Processing word 0: "eat".
Why sorted letters (or letter counts) work as a key: sorting is order-independent — "eat" and "tea" both sort to "aet". A 26-length count tuple works too, and avoids the O(k log k) sort cost, trading it for a flat O(k) tally — the optimal version in the code below.

Optimal Solution — Letter-Count Key · O(n·k) time, O(n·k) space

from collections import defaultdict

def group_anagrams(strs: list[str]) -> list[list[str]]:
    groups = defaultdict(list)
    for w in strs:
        counts = [0] * 26
        for c in w:
            counts[ord(c) - ord('a')] += 1
        groups[tuple(counts)].append(w)     # tuple is hashable -> valid dict key
    return list(groups.values())

n words of length up to k → O(n·k) time (no sort needed, just a flat tally). Storing all words in buckets → O(n·k) space.

The core flip — mirror comparison from both ends

A palindrome reads the same forwards and backwards, so the first useful character must equal the last, the second must equal the second-last, and so on. Two pointers close in from both ends, skipping anything that isn't a letter or digit.

Why filter while scanning instead of building a cleaned copy first: the two-pointer version needs zero extra memory — it just skips non-alphanumeric characters in place on both sides before each comparison, achieving the same result as a "clean, then reverse and compare" approach but in O(1) space instead of O(n).

Optimal Solution — Two Pointers, In-Place · O(n) time, O(1) space

def is_palindrome(s: str) -> bool:
    i, j = 0, len(s) - 1
    while i < j:
        while i < j and not s[i].isalnum():
            i += 1                    # skip non-letters/digits on the left
        while i < j and not s[j].isalnum():
            j -= 1                    # skip non-letters/digits on the right
        if s[i].lower() != s[j].lower():
            return False               # mirror mismatch -> not a palindrome
        i += 1; j -= 1
    return True

Pointers only move inward, each index visited once → O(n) time. No extra copy of the string → O(1) space.

The core flip — most-recent opener closes first

Brackets nest like boxes inside boxes: the last one you open must be the first you close. A stack remembers openers in exactly that order — push every opener, and when a closer arrives it must match whatever is currently on top.

Press "Step" to begin. i=0.
Two failure modes to catch: a closer arriving when the stack is empty (nothing to close), or a closer whose type doesn't match the top of the stack (wrong pairing, like "([)]"). At the end, the stack must also be completely empty — leftover openers mean something was never closed.

Optimal Solution — Stack · O(n) time, O(n) space

def is_valid(s: str) -> bool:
    match = {")": "(", "]": "[", "}": "{"}
    stack = []
    for c in s:
        if c in match:                # c is a CLOSER
            if not stack or stack[-1] != match[c]:
                return False           # nothing to close, or wrong type
            stack.pop()
        else:                          # c is an OPENER
            stack.append(c)
    return not stack                   # valid only if every opener was closed

Single pass, O(1) work per character → O(n) time. Stack holds at most n openers → O(n) space.

The core flip — say the size before the content

Packing a list of strings into one string is dangerous with a plain separator — the data itself might contain that separator. The fix: write each string's length before it, so decoding always knows exactly how many characters to read, no matter what those characters are.

Why a naive separator (like "#") breaks: if any input string itself contains "#", decoding can't tell whether that # is a real separator or part of the data. Try encoding ["a#b"] naively — splitting on "#" silently corrupts it into two strings, ["a", "b"], and the original is lost.

Optimal Solution — Length-Prefix Encoding · O(total length) time & space

def encode(strs: list[str]) -> str:
    parts = []
    for w in strs:
        parts.append(str(len(w)) + "#" + w)   # "#"
    return "".join(parts)

def decode(s: str) -> list[str]:
    res = []
    i = 0
    while i < len(s):
        j = i
        while s[j] != "#":            # read digits up to the '#' marker
            j += 1
        length = int(s[i:j])          # those digits are the content length
        start = j + 1
        res.append(s[start:start + length])   # read exactly `length` chars — any char is safe
        i = start + length
    return res

Every character is written and read exactly once → O(total length) time and space. Because the reader is told exactly how far to read, the content can safely contain any character, including the # marker itself.
