The core flip

A mirror image swaps left and right everywhere. Visit every node with DFS (or BFS) and swap its two children — the recursive calls handle inverting everything below automatically. Any full traversal order works, since the swap at each node is independent of the others.

tree = [4, 2, 7, 1, 3, 6, 9]
Press "Step" to begin. Visiting root (4): about to swap its children.
currently visiting children already swapped
Why a simultaneous assignment matters: root.left, root.right = invert(root.right), invert(root.left) computes both inverted subtrees before assigning either — swapping the raw references first and then recursing into the wrong (already-swapped) slots would silently corrupt the tree.

Optimal Solution — Recursive DFS · O(n) time, O(h) space

def invert_tree(root):
    if not root:
        return None
    root.left, root.right = invert_tree(root.right), invert_tree(root.left)
    return root

Every node visited once → O(n) time. Recursion stack depth = tree height → O(h) space (O(log n) balanced, O(n) worst case skewed).

The core flip

Depth is just "how many levels tall". The classic tree-recursion template: a node's answer = combine its children's answers. Here, depth(node) = 1 + the deeper of its two children's depths — an empty tree has depth 0, the base case that makes the recursion terminate.

Depth vs height, and node vs edge counting: this LeetCode-style depth counts nodes on the path (empty subtree → 0, single node → 1) — different from the edge-counting convention where a single node has height 0. Always match whichever base case the problem specifies.

Optimal Solution — Recursive DFS · O(n) time, O(h) space

def max_depth(root):
    if not root:
        return 0
    return 1 + max(max_depth(root.left), max_depth(root.right))

Every node visited once → O(n) time. Recursion stack depth = tree height → O(h) space.

The core flip

Two trees are identical only if their roots match and their left subtrees match and their right subtrees match. Walk both trees together — the same question, asked in lockstep on corresponding positions of both.

p = [1,2,3]   q = [1,2,3]
Press "Step" to begin. Comparing roots: p=1, q=1.
currently comparing matched mismatch
Order of checks matters: check "both empty" and "one empty / values differ" before recursing — skipping straight to comparing .val on a possibly-None node would crash. This base-case ordering is the most common bug source in tree-comparison problems.

Optimal Solution — Parallel Recursive DFS · O(n) time, O(h) space

def is_same_tree(p, q):
    if not p and not q:
        return True
    if not p or not q or p.val != q.val:
        return False
    return is_same_tree(p.left, q.left) and is_same_tree(p.right, q.right)

Every node pair visited once → O(n) time. Recursion depth = tree height → O(h) space.

The core flip

sub is a subtree of root if, at some node of root, the tree hanging there is identical to sub. This reuses the "Same Tree" check as a sub-routine, called at every node of root — a common pattern where a simpler check gets applied repeatedly across a structure.

root = [3,4,5,1,2]   sub = [4,1,2]
Press "Step" to begin. Checking node 3: is the tree here == sub?
checking this node as a candidate root match found!
Faster alternative — serialize and search: flatten both trees to strings with explicit markers for values and empty children (e.g. "^4 ^1 # # ^2 # #"), then check if sub's string is a substring of root's. This turns an O(m·n) tree-comparison problem into an O(m+n) string-search problem — but markers are essential, or "12" could wrongly match inside "2".

Two Approaches

# Approach 1 — Same-tree check at every node · O(m·n) time, O(h) space
def is_subtree(root, sub):
    if not sub:
        return True
    if not root:
        return False
    if is_same_tree(root, sub):     # reuse the Same Tree check
        return True
    return is_subtree(root.left, sub) or is_subtree(root.right, sub)

# Approach 2 — Serialize + substring search · O(m+n) time, O(m+n) space
def is_subtree_fast(root, sub):
    def serialize(node):
        if not node:
            return "#"                # marker for empty child
        return "^" + str(node.val) + " " + serialize(node.left) + " " + serialize(node.right)
    return serialize(sub) in serialize(root)

Approach 1: O(m) comparison at up to n nodes → O(m·n). Approach 2: two linear serializations plus a linear substring search → O(m+n), strictly better for large trees.
