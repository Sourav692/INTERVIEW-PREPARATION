The core flip

Flood fill is the engine: scan every cell, and the moment you hit unvisited land, spread (DFS or BFS) across the entire connected blob, marking it visited ("sinking" it) so it's never recounted. Each fresh flood-fill start is exactly one island.

Why "sink as you go" beats a separate visited set: overwriting a visited land cell to water directly in the grid means one array does double duty — no extra memory needed to track what's been seen, and checking "is this still land?" is the same check as "have I visited this?"

Optimal Solution — DFS Flood Fill · O(rows·cols) time, O(rows·cols) worst-case space

def num_islands(grid):
    rows, cols = len(grid), len(grid[0])
    def sink(r, c):
        if r<0 or c<0 or r>=rows or c>=cols or grid[r][c] != "1":
            return                        # off-grid or water/already-sunk -> stop
        grid[r][c] = "0"                  # sink this land cell (mark visited)
        sink(r+1,c); sink(r-1,c); sink(r,c+1); sink(r,c-1)   # spread to 4 neighbors

    count = 0
    for r in range(rows):
        for c in range(cols):
            if grid[r][c] == "1":         # found a NEW, unvisited island
                count += 1
                sink(r, c)                # flood-fill (sink) the whole blob
    return count

Each cell visited once → O(rows·cols) time. Worst-case recursion depth (one giant island) → O(rows·cols) space (BFS with a queue caps this at O(min(rows,cols))).

The core flip

Checking "can water FROM this cell reach the ocean?" for every cell is O((rows·cols)²) — way too slow. Instead, flip the question: climb inland from the ocean borders to equal-or-higher cells (the reverse of water flowing downhill). A cell that's reachable by climbing from both oceans is exactly a cell whose water can flow to both.

Why this is "multi-source" flood fill: instead of one starting cell, every Pacific-border cell is a starting point simultaneously — the DFS/BFS just explores from all of them at once (into a shared "reached" set). Doing this once per ocean, then intersecting the two reached sets, replaces (rows·cols) separate searches with exactly 2.

Optimal Solution — Climb From Borders · O(rows·cols) time, O(rows·cols) space

def pacific_atlantic(heights):
    rows, cols = len(heights), len(heights[0])
    pac, atl = set(), set()
    def dfs(r, c, seen, prev):
        if (r,c) in seen or r<0 or c<0 or r>=rows or c>=cols or heights[r][c] < prev:
            return                        # can't climb UP into a lower cell
        seen.add((r, c))
        for dr, dc in ((1,0),(-1,0),(0,1),(0,-1)):
            dfs(r+dr, c+dc, seen, heights[r][c])

    for c in range(cols):                 # seed Pacific (top row) & Atlantic (bottom row)
        dfs(0, c, pac, heights[0][c]); dfs(rows-1, c, atl, heights[rows-1][c])
    for r in range(rows):                 # seed Pacific (left col) & Atlantic (right col)
        dfs(r, 0, pac, heights[r][0]); dfs(r, cols-1, atl, heights[r][cols-1])

    return [[r,c] for r in range(rows) for c in range(cols) if (r,c) in pac and (r,c) in atl]

Each ocean's search visits each cell at most once → O(rows·cols) time for both combined. Two "reached" sets plus recursion → O(rows·cols) space.

The core flip

Start with every node in its own group. Each edge that joins two different groups merges them, shrinking the group count by one. Union-Find (Disjoint Set) tracks this efficiently: find(x) returns x's group leader, union(a,b) merges two groups. Final component count = groups remaining.

Why the answer is just "count minus successful merges": every node starts isolated (n groups). Each edge either joins two already-connected nodes (no-op, already counted together) or bridges two separate groups (one fewer group). No traversal needed — the arithmetic alone gives the answer.

Optimal Solution — Union-Find · O((n+E)·α(n)) ≈ O(n+E) time, O(n) space

def count_components(n, edges):
    parent = list(range(n))          # each node starts as its own group leader
    count = n
    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]   # path compression
            x = parent[x]
        return x
    for a, b in edges:
        ra, rb = find(a), find(b)
        if ra != rb:                  # different groups -> merging reduces the count
            parent[ra] = rb
            count -= 1
    return count

With path compression, near-constant amortized time per operation → O(n+E) effectively. Parent array → O(n) space. (Traversal counting fresh starts is an equally valid O(n+E) alternative.)

The core flip

A graph is a tree iff it is fully connected and has no cycle. The cheapest filter: a tree on n nodes has exactly n−1 edges — check that first. Then run Union-Find: if an edge's two endpoints are already in the same group, that edge creates a cycle → not a tree.

Why the edge-count check alone isn't sufficient: exactly n−1 edges rules out cycles if the graph is also fully connected — but n−1 edges could still be split into a smaller cycle plus disconnected pieces. That's why Union-Find is still needed: it directly verifies no cycle forms as edges merge, which (combined with the correct edge count) guarantees full connectivity as a consequence.

Optimal Solution — Edge Count + Union-Find Cycle Check · O(n) time, O(n) space

def valid_tree(n, edges):
    if len(edges) != n - 1:          # a tree on n nodes has EXACTLY n-1 edges
        return False
    parent = list(range(n))
    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]
            x = parent[x]
        return x
    for a, b in edges:
        ra, rb = find(a), find(b)
        if ra == rb:                  # already in the same group -> this edge is a CYCLE
            return False
        parent[ra] = rb
    return True                       # n-1 edges + no cycle => connected tree

Edge check is O(1); Union-Find loop is near-linear → O(n) time overall. Parent array → O(n) space.
