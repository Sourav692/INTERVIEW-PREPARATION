🧩 Dynamic Programming Patterns — Interview Cheat Sheet

Eleven problems, but only a handful of ideas. Learn to spot which one a question is asking for.

🔢 Fibonacci-Style 1-D DP

Each answer is built from the previous one or two — like Fibonacci.

The tell (how to spot it): You’re counting ways or optimizing along a line where each step depends on the last few.

How it works: Define dp[i] from dp[i-1] and dp[i-2] (with rules). Fill from the base cases up; often you only need the last couple of values, so memory drops to O(1).

Problems here that use it: Climbing Stairs Decode Ways House Robber House Robber II

Say this in the interview:
“Each state depends only on the previous one or two, so I’ll fill a 1-D table (or two rolling variables) — that’s O(n).”

🎯 Build Up to a Target

To make change for $6, first know how to make $5, $4, …

The tell (how to spot it): You build a number/amount/prefix from smaller ones, trying several choices at each step.

How it works: dp over amounts or prefixes: for each value, try every option (coin, word, cut) and combine with the already-solved smaller value.

Problems here that use it: Coin Change Word Break

Say this in the interview:
“I’ll build every smaller amount/prefix first and combine — don’t trust greedy; DP tries all options in O(target × choices).”

🗺️ 2-D Grid DP

Fill a table where each cell leans on its neighbors already filled in.

The tell (how to spot it): Two sequences to compare, or a grid to move through.

How it works: Make an (m+1)×(n+1) table. Each cell combines earlier cells: match → diagonal+1, or sum of the cell above and to the left.

Problems here that use it: Longest Common Subsequence Unique Paths

Say this in the interview:
“I’ll fill a 2-D table where each cell builds on the diagonal/up/left neighbors — O(m×n).”

📈 'Best Ending Here'

For each spot, find the best run that finishes right there.

The tell (how to spot it): Longest/optimal subsequence where each element extends earlier ones.

How it works: dp[i] = the best answer that ends at i, built from compatible earlier positions. Take the overall best at the end.

Problems here that use it: Longest Increasing Subsequence

Say this in the interview:
“I’ll track the best subsequence ending at each index and take the max — O(n²), or O(n log n) with binary search.”

⚡ Greedy Beats DP

Sometimes one clever running value replaces the whole table.

The tell (how to spot it): A DP works, but a single sweep with a running best (farthest reach, running max) suffices.

How it works: Prove the local choice is always safe, then sweep once carrying that value — dropping O(n²)/O(n) space to O(n)/O(1).

Problems here that use it: Jump Game

Say this in the interview:
“The greedy running value is provably safe here, so I’ll sweep once and skip the table — O(n), O(1) space.”

🌳 Backtracking (Choose / Explore / Undo)

Try a path in a maze; if it dead-ends, step back and try another.

The tell (how to spot it): You must list all combinations, subsets, or arrangements — not just count or optimize.

How it works: Recurse: make a choice, explore, then undo it. A start index avoids duplicate sets; sorting lets you prune when a choice overshoots.

Problems here that use it: Combination Sum

Say this in the interview:
“Since I need every combination, I’ll backtrack — choose, recurse, undo — with a start index to avoid duplicates.”

Talking through any DP problem

1. Say the brute force. "Try every choice recursively" — then notice it recomputes the same subproblems (that’s the DP signal).

2. Name the state. What does dp[i] (or dp[i][j]) mean? Write the recurrence and the base cases.

3. Pick a fill order so every value is ready when you need it (bottom-up), then shrink memory if only recent values matter.

4. Ask if greedy works — sometimes a single running value replaces the whole table.
