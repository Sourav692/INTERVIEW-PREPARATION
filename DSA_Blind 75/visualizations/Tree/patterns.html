🧩 Tree Patterns — Interview Cheat Sheet

Fourteen problems, but only a handful of ideas. Learn to spot which one a question is asking for.

🌳 Tree Recursion (DFS)

Ask each node the same question, and let it ask its children.

The tell (how to spot it): Almost any tree problem — depth, comparing, inverting, validating, path sums.

How it works: Write a function that handles one node by combining the answers from its children. The base case is the empty node. This one shape solves a huge share of tree problems.

Problems here that use it: Maximum Depth Same Tree Invert Binary Tree Validate BST

Say this in the interview:
“I’ll recurse: solve each node by combining its children’s results, with the empty node as the base case — that’s O(n).”

🪣 Level-by-Level (BFS with a Queue)

Peel the tree like an onion, one layer at a time.

The tell (how to spot it): You need things grouped by level/depth, or the shortest number of steps.

How it works: Use a queue. The nodes currently in it form one level; empty them into a row while pushing their children for the next level.

Problems here that use it: Level Order Traversal Maximum Depth

Say this in the interview:
“This is level-by-level, so I’ll BFS with a queue and process one full level per round.”

🧭 Use the BST Order Rule

In a search tree, smaller is always left and larger is always right — so you can steer.

The tell (how to spot it): The tree is a BST and you’re searching, validating, or picking by rank.

How it works: Two superpowers: (1) an in-order walk comes out sorted; (2) you can walk straight toward a target, skipping half the tree each step.

Problems here that use it: Validate BST Kth Smallest in a BST Lowest Common Ancestor (BST)

Say this in the interview:
“It’s a BST, so an in-order walk is sorted and I can navigate by comparing to each node — that keeps it to O(height).”

🗺️ Traversal Orders (Preorder / Inorder)

The order you visit nodes carries information you can rebuild from.

The tell (how to spot it): You’re rebuilding a tree, or need a canonical snapshot of it.

How it works: Preorder lists roots first; inorder splits left/right; adding null markers makes the snapshot lossless so you can reconstruct the exact tree.

Problems here that use it: Construct from Preorder & Inorder Serialize and Deserialize

Say this in the interview:
“Preorder gives me the root and inorder splits left from right, so I can rebuild the tree — with a hash map that’s O(n).”

🔁 Return One Thing, Track Another

Hand your boss a summary, but quietly keep the record of the best you’ve seen.

The tell (how to spot it): The answer can appear anywhere in the tree, not just at the root (max path, diameter).

How it works: A DFS returns a value useful to the parent (e.g. the best single downward arm) while separately updating a global best (e.g. the full bent path through the node).

Problems here that use it: Binary Tree Maximum Path Sum

Say this in the interview:
“I’ll DFS returning the best single arm to the parent, but update a global best with the full path through each node.”

🗂️ Trie (Prefix Tree) + DFS

A shared family tree of words — common beginnings share a branch.

The tell (how to spot it): The problem is about prefixes, dictionaries, or matching many words at once.

How it works: Store words letter by letter so shared prefixes share a path. Then prefix checks are instant, wildcards branch with DFS, and a whole word list can steer one grid search.

Problems here that use it: Implement Trie Add and Search Word Word Search II

Say this in the interview:
“Since it’s about prefixes / many words, I’ll build a trie — each lookup is O(word length) regardless of how many words I stored.”

Talking through any Tree problem

1. Reach for recursion first. "Solve each node by combining its children" fits most tree problems — say the base case (empty node) out loud.

2. Look for a tell. Levels/shortest → BFS queue. It’s a BST → in-order is sorted / navigate by comparison. Rebuild/save → traversal orders + markers. Answer anywhere → return one thing, track a global best. Prefixes/many words → trie.

3. State the cost. Most full traversals are O(n); BST navigation is O(height); trie ops are O(word length).

4. Mind the edges: empty tree, a single node, and very deep (skewed) trees where recursion could get tall.
