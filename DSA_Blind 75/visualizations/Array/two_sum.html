1 · Two Sum

Find two numbers in a list that add up to a target.

The problem, in plain words

You have a list of numbers and a target total. Find the two numbers that add up to that target, and return where they are (their positions).

Think of a shopping receipt. The bill should be $26. Which two item prices add up to exactly $26?

Our example list: [2, 7, 11, 15]  ·  target = 26. The answer is 11 + 15 (positions 2 and 3).
looking at remembered match / answer ruled out

Way 1 — Try every pair (the obvious way)

Pick the first number, then check it against every number after it. If none work, move to the next first number. Keep going until a pair adds up to the target.

Speed: checks every pair, so it gets slow fast on big lists — O(n²) time, O(1) extra memory.

Way 2 — Sort, then close in from both ends

Put the numbers in order first. Start one finger at the smallest, one at the largest. If their sum is too small, move the left finger right (to get bigger). If it's too big, move the right finger left. Meet in the middle.

Speed: sorting takes O(n log n), the walk is O(n). Faster than Way 1, but sorting loses the original positions (we track them separately).

Way 3 — Remember what you've seen (the best way)

Go through once. For each number, work out its partner (target minus this number). Have we seen that partner already? If yes — done! If no, remember this number and move on. "Remembering" uses a hash map: a notebook where you can look something up instantly.

Memory (numbers seen so far → their position)

Speed: one pass, and each lookup is instant — O(n) time, O(n) memory. This is the answer you give in an interview.

When you'd use each idea

See the words "find two things that add up to X"? Reach for the hash map — remember what you've seen and look up the partner instantly. If the list is already sorted (or you don't mind sorting), the two-finger trick works with no extra memory.
