🧩 Array Patterns — Interview Cheat Sheet

🧠 Remember What You’ve Seen (Hash Map / Set)

Like keeping a guest list at the door — you can check “have I seen this before?” instantly.

The tell (how to spot it): You’re searching for a partner, a duplicate, or “does X exist?” inside a loop.

How it works: Walk through once. For each item, look up what you need in your memory (instant). If it’s there, done; if not, add the item and keep going. This turns a slow “check every pair” into a single pass.

Problems here that use it: Two Sum Contains Duplicate

Say this in the interview:
“I’m searching for a match, so I’ll keep a hash set of what I’ve seen and look up the partner in one step — that makes it linear time.”

👉👈 Two Fingers From Both Ends (Two Pointers)

One finger at each end of a sorted row, closing in toward the middle.

The tell (how to spot it): The data is sorted (or you can sort it) and you want a pair or trio, or the best width × height.

How it works: Start wide. Look at the two ends; based on whether their combination is too big or too small, move the finger that can only help. You cover all useful pairs in one sweep, no nested loops.

Problems here that use it: Container With Most Water 3Sum

Say this in the interview:
“Since it’s sorted, I’ll use two pointers from both ends and move the one that improves my result — that’s linear after the sort.”

🏃 One Pass, Keep a Running Best (Kadane / Tracking)

Like watching a scoreboard: you don’t re-count from scratch, you just update the total as you go.

The tell (how to spot it): You want the best run / best profit / best total and each step depends only on the step before.

How it works: Carry one or two running values as you sweep (a running total, a cheapest-so-far, a biggest-and-smallest). Update the overall best each step. Drop the running value when it stops helping.

Problems here that use it: Best Time to Buy and Sell Stock Maximum Subarray Maximum Product Subarray

Say this in the interview:
“The answer for each position only depends on the previous one, so I’ll keep a running value and the best-so-far in a single pass — linear time, no extra memory.”

↔️ Build From Both Directions (Prefix / Suffix)

Two people fill in a form — one starts from the top, the other from the bottom — then you combine their notes.

The tell (how to spot it): Each answer needs “everything on one side” — a running sum or product to the left and/or right.

How it works: Do one sweep left-to-right recording the running result before each spot, and one sweep right-to-left multiplying (or adding) in the rest. Combining the two directions gives each answer in constant time.

Problems here that use it: Product of Array Except Self

Say this in the interview:
“Each result depends on everything except the current item, so I’ll precompute running products from the left and right and combine — linear time and no division.”

✂️ Halve the Search (Binary Search)

Guessing a number 1–100: guess the middle, and each guess throws away half.

The tell (how to spot it): The data is sorted (even sorted-then-rotated) and you need it fast (O(log n)).

How it works: Look at the middle and use a simple rule — compare it to an end — to decide which half can’t hold the answer. Throw that half away and repeat. In a rotated list, first spot which half is in proper order.

Problems here that use it: Find Minimum in Rotated Sorted Array Search in Rotated Sorted Array

Say this in the interview:
“It’s sorted, so I’ll binary search — check the middle, decide which half to keep, and repeat. That’s log-n time.”

🔣 Sort First to Reveal Structure

Tidy your desk before working — once things are in order, patterns jump out.

The tell (how to spot it): Order would make the problem easier — duplicates sit together, or two-pointer / binary search becomes possible.

How it works: Spend one O(n log n) sort up front. Afterwards, equal items are neighbors (easy to skip duplicates) and you can walk with two pointers or binary search.

Problems here that use it: 3Sum Contains Duplicate

Say this in the interview:
“If I sort first, duplicates line up and I can use two pointers — the sort cost is worth the simpler, faster scan afterwards.”

Talking through any Array problem

A simple routine that works in interviews:

1. Say the brute-force first. “The obvious way is to check every pair, but that’s slow (n²).” It shows you understand the problem.

2. Look for a tell. Searching for a match → remember what you’ve seen. Sorted → two pointers or binary search. Best run/total → running value. “Everything except me” → prefix/suffix.

3. State the speed. Name the time and memory of your better idea, and why it’s faster.

4. Think out loud and test a tiny example (like the animations here) before you code.
