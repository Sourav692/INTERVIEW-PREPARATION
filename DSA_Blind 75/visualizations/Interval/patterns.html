🧩 Interval Patterns — Interview Cheat Sheet

A few ideas cover the whole topic. Learn to spot which one a question wants.

Sort Then SweepGreedy by Earliest EndCount Overlaps (Sweep / Heap)

📐 Sort Then Sweep

Line the intervals up by start (or end), then walk once.

The tell (how to spot it): Almost every interval problem — merge, insert, overlap checks.

How it works: Sort by start (to merge) or by end (to keep the most). Then a single left-to-right pass handles overlaps because they’re now adjacent.

Problems here that use it: Merge Intervals Insert Interval Meeting Rooms

Say this in the interview:
“I’ll sort the intervals and sweep once — overlaps become adjacent, so it’s O(n log n).”

🎯 Greedy by Earliest End

Keep whatever finishes soonest — it frees you up fastest.

The tell (how to spot it): You want the most non-overlapping intervals (or fewest removals).

How it works: Sort by end time and keep an interval only if it starts after the last kept one ended.

Problems here that use it: Non-overlapping Intervals

Say this in the interview:
“To keep the most, I’ll sort by end time and greedily keep the earliest-finishing interval — that’s optimal.”

📈 Count Overlaps (Sweep / Heap)

Tally how many are active at once as time moves forward.

The tell (how to spot it): You need the max concurrent intervals (rooms, servers).

How it works: Turn intervals into +1 (start) / −1 (end) events sorted by time, or keep a heap of end times; the peak count is the answer.

Problems here that use it: Meeting Rooms II

Say this in the interview:
“Rooms needed is the max overlap, so I’ll sweep +1/−1 events (or use a heap of end times) and track the peak — O(n log n).”

Talking through any Interval problem

1. Sort first — by start to merge, by end to keep the most.

2. Define overlap precisely: [a,b] and [c,d] overlap when a ≤ d and c ≤ b (mind touching endpoints).

3. For "how many at once", think events (+1/−1) or a heap of end times.
