🧩 Graph Patterns — Interview Cheat Sheet

Eight problems, but only a handful of ideas. Learn to spot which one a question is asking for.

🔎 Traverse with a Visited Set (DFS / BFS)

Explore a maze while chalk-marking rooms you’ve entered so you never loop.

The tell (how to spot it): Almost any graph task — copying, reaching, connectivity — needs a walk that won’t loop.

How it works: Walk the graph with recursion/stack (DFS) or a queue (BFS), remembering visited nodes. DFS goes deep; BFS spreads in rings (best for fewest-steps).

Problems here that use it: Clone Graph Number of Islands

Say this in the interview:
“I’ll traverse with DFS/BFS and a visited set so I handle each node once and don’t loop — that’s O(V+E).”

🌊 Flood Fill on a Grid

The paint-bucket tool: click a cell and the color spreads to all connected matching cells.

The tell (how to spot it): A grid where you count or spread through connected regions.

How it works: Scan the grid; from each new region, DFS/BFS to all matching neighbors, marking them so you don’t recount. Searching backwards from borders is a powerful twist.

Problems here that use it: Number of Islands Pacific Atlantic Water Flow

Say this in the interview:
“It’s a grid of connected regions, so I’ll flood-fill each region once — O(rows×cols).”

🔗 Topological Sort (Ordering with Dependencies)

Doing chores in an order where every prerequisite comes first.

The tell (how to spot it): You must order things under "do X before Y" rules, or detect an impossible cycle.

How it works: Build a directed graph, count each node’s prerequisites, and repeatedly take one with none left. If some never come free, there’s a cycle.

Problems here that use it: Course Schedule Alien Dictionary

Say this in the interview:
“These are dependencies, so I’ll topologically sort — take zero-prerequisite nodes repeatedly; leftovers mean a cycle.”

🧲 Union-Find (Group Merging)

Merging friend circles: when two people connect, their whole circles become one.

The tell (how to spot it): You’re counting groups, or checking connectivity / cycles in an undirected graph.

How it works: Each node starts alone. Union merges two groups; find returns a group’s leader. Joining two already-together nodes reveals a cycle.

Problems here that use it: Graph Valid Tree Number of Connected Components

Say this in the interview:
“I’ll use Union-Find: merge endpoints of each edge; the number of groups left is the answer, and a same-group edge is a cycle.”

🧠 A Set Can Be a Graph

Numbers that follow each other form invisible chains you can walk.

The tell (how to spot it): Items are implicitly linked (consecutive numbers, neighbors) with no explicit edges given.

How it works: Put items in a set for O(1) lookups and ‘walk’ the implied links (e.g. from a run’s start, step to the next number).

Problems here that use it: Longest Consecutive Sequence

Say this in the interview:
“The links are implicit, so I’ll use a set and only grow each chain from its start — that keeps it O(n).”

Talking through any Graph problem

1. Name the graph. What are the nodes and edges? Is it directed? Is it a grid in disguise?

2. Look for a tell. Reach / copy / connected → DFS/BFS with visited. Grid regions → flood fill. Dependencies/ordering → topological sort. Count groups / cycles → Union-Find.

3. Always track visited so you never loop, and state the cost — most graph walks are O(V+E).

4. Mind the edges: disconnected pieces, isolated nodes, empty graph, and cycles.
