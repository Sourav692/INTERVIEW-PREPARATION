2. Sliding Window Maximum

Hard · Arrays / Queues

The problem, in plain words

You have an array and a window size k. Slide a window of size k across the array, one step at a time. At every position, report the biggest number currently inside the window.

nums = [1, 3, -1, -3, 5, 3, 6, 7], k = 3 window maxes: [3, 3, 5, 5, 6, 7]

Results so far

Approach 1 — Rescan every window (the slow way)

For every window position, look at all k numbers inside it and find the max from scratch. That's what the demo above did. For n numbers this costs O(n × k) — close to O(n²) when k is large, because you keep re-checking numbers you already looked at in the last window.

Approach 2 — Monotonic deque (the fast way)

The idea: keep a line of "candidates that could still win," always sorted biggest-to-smallest. Before adding a new number, kick out anyone at the back who's smaller — they're beaten for good, since the new number is both bigger and will stay in the window longer. The front of the line is always the current max.

Results so far

Speed & memory: every number enters and leaves the candidate line at most once across the whole run → O(n) time total, O(k) space for the line.

When you'd reach for this

Any time you need a rolling max or min over a sliding window efficiently: rolling peak load on a dashboard, "max/min over every window of size k", nearest-greater-element style problems.
