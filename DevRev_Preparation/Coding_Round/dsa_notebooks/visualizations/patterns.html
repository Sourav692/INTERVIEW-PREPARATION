Interview tips

  • Say the tell out loud. "We need contiguous sums, and values can be negative, so I'll use prefix sum + hash map instead of a sliding window" shows you're pattern-matching, not guessing.
  • Name the data structure's job, not just its name. "A hash map so I can look this up in O(1) instead of scanning" is more convincing than just "I'll use a dict."
  • State the naive approach's complexity first, then explain what specifically makes your optimized approach faster (fewer re-scans, O(1) eviction, one pass instead of many).
  • If a trick doesn't fit, say why — e.g. "sliding window won't work here because of negative numbers" is a strong signal you understand the tool, not just the trick.
