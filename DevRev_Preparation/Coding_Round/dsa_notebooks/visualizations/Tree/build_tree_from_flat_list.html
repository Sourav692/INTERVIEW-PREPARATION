5. Build a Tree from a Flat List

Medium · Trees / Hash Maps

The problem, in plain words

Databases store hierarchies as flat rows — each row just has its own id and its parent_id. Turn that flat list back into a real nested tree.

{id:1, parent_id:None} Epic: Login {id:2, parent_id:1} Backend {id:3, parent_id:1} Frontend {id:4, parent_id:2} Auth API {id:5, parent_id:99} Orphan task (parent doesn't exist!)

Watch the tree get built, two passes

Pass 1 creates an empty "node" for every record and drops it in a lookup table (so any id can be found instantly). Pass 2 walks the records again and links each one under its parent — using the lookup table instead of scanning.

Approach 1 — Scan for each parent (the slow way)

For every record, scan the whole list to find the row whose id matches its parent_id. For n records that's an O(n) scan per record → O(n²) total.

Approach 2 — Hash-map index + one pass (the fast way)

The idea: build an id → node lookup table first (Pass 1). Then in one more pass, look each parent up in O(1) and attach the child. That's exactly what the animation above shows.

Speed & memory: two linear passes → O(n) time, O(n) space for the lookup table.

When you'd reach for this

Any time you catch yourself thinking "find the record with this id" inside a loop — that's the signal to build a dictionary first. Rendering task/comment trees, org charts, category hierarchies from flat DB rows.
