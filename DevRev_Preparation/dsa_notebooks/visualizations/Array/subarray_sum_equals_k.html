1. Subarray Sum Equals K

Medium · Arrays / Hash Maps

The problem, in plain words

You get a list of numbers and a target number k. Count how many stretches of numbers sitting next to each other (contiguous subarrays) add up to exactly k.

Real-world flavor: imagine a row of daily expenses. "How many runs of consecutive days did I spend exactly $50 in total?" — that's this problem.

nums = [1, 2, 3], k = 3 matches: [1,2] (sums to 3) and [3] (sums to 3) → answer = 2

Approach 1 — Check every stretch (the slow way)

For every possible start, keep extending the end one step at a time, adding a running total. Any time that running total equals k, count it. Simple, but you redo work: for n numbers this checks roughly n² stretches — O(n²).

This is exactly what the demo above just showed you.

Approach 2 — Prefix sum + hash map (the fast way)

Walk through the array once, keeping a running total. At each position, ask: "has the running total been exactly (current total − k) at some earlier point?" If yes, every one of those earlier points is the start of a stretch ending here that sums to k. A hash map remembers every running total we've seen (and how many times), so this lookup is instant.

When you'd reach for this

Whenever you see "count/find a contiguous stretch that sums to a target" — especially if the numbers can be negative (which rules out a sliding window, because the running sum stops being monotonic). Seed the map with {0: 1} so a stretch starting at index 0 is counted correctly.
