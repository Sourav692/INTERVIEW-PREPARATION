7. LRU Cache

Medium · Hash Map + Doubly Linked List

The problem, in plain words

Build a cache holding a fixed number of items. get(key) returns the value (or -1). put(key,value) inserts/updates. When full, evict the Least Recently Used item. Both operations must be instant — O(1) — no matter how big the cache gets.

cache = LRUCache(capacity=2) put(1,1); put(2,2) get(1) -> 1 (using 1 makes it "most recent") put(3,3) -> evicts key 2 (least recently used) get(2) -> -1

Approach 1 — Dict + plain order list (the slow way)

Keep values in a dict, plus a plain list of keys in use-order. Every touch removes the key from wherever it sits in the list and appends it at the end. Removing from the middle (or front) of a plain list means shifting every element after it → O(n) per operation.

Approach 2 — Hash map + doubly linked list (the fast way)

The idea: a dict maps key → node instantly. The nodes also live in a doubly linked list ordered by recency. Unlinking a node and re-inserting it at the front costs O(1) — no shifting, because each node just points to its neighbors directly. That's exactly what the animation above shows.

Speed & memory: O(1) for both get and put, O(capacity) space. Dummy head/tail sentinel nodes remove all the "is this the first/last node?" edge cases.

When you'd reach for this

"O(1) get/set with eviction", "least/most recently used", "bounded cache with a fixed size" — response caches, session caches, memoizing expensive calls.
