6. Lowest Common Ancestor of a Binary Tree

Medium · Trees / DFS

The problem, in plain words

Given a tree and two nodes p and q, find their lowest common ancestor — the deepest node that has both of them somewhere below it (a node counts as its own ancestor).

3 / \ 5 1 / \ / \ 6 2 0 8 / \ 7 4 LCA(5, 1) = 3 (they only meet at the root) LCA(5, 4) = 5 (5 is itself an ancestor of 4)

Purple ring = one of our two targets (p=5, q=1). Unlike a search tree, values aren't sorted here — you can't "navigate" toward the answer, you have to search.

Approach 1 — Root-to-node paths (works, but uses more memory)

The idea: find the path from the root down to p, and the path down to q. Walk both paths together from the start — the last node they still agree on is the LCA.

Path to p=5

Path to q=1

Speed & memory: O(n) time, but O(n) extra space for the two stored paths.

Approach 2 — Single recursive DFS (the optimal way)

The idea: search both children and ask each "did you find p or q down there?" If both sides answer yes, the current node is the split point — the LCA. If only one side answers, pass that answer up.

target (p or q) currently visiting found: LCA!

Speed & memory: O(n) time, only O(height) space (the recursion stack) — no stored paths needed.

When you'd reach for this

"Deepest common parent / where two nodes meet" in a tree with no ordering to exploit (a BST would let you compare values and navigate in O(height) instead). Also watch for the case where one target is itself an ancestor of the other — like LCA(5,4)=5 above — the recursion returns as soon as it hits node 5, no need to search further down that branch.
