3. Topological "Wave" Scheduling

Medium · Graphs / Topological Sort

The problem, in plain words

You have tasks, and some tasks need others finished first (a dependency graph, arrows point "this unlocks that"). Group the tasks into waves: everything with zero remaining prerequisites runs together, then the next wave, and so on. If two tasks depend on each other in a loop, it's impossible — that's a cycle.

Approach 1 — Rescan every dependency each round (the slow way)

Each round: recompute every remaining task's prerequisite count by scanning all dependencies from scratch, take whatever's ready, remove it, repeat. Correct, but you redo the same scan every round → O(tasks × dependencies).

Approach 2 — Kahn's algorithm, grouped by wave (the fast way)

The idea: count every task's prerequisites once up front. Anything at 0 is ready — that's a wave. When a task finishes, tell its dependents "one prerequisite done" (subtract 1). Any dependent that hits 0 becomes ready for the next wave. This is exactly what the animation above just showed.

Speed & memory: each dependency edge is walked exactly once, total → O(tasks + dependencies) time and space.

When you'd reach for this

"Run tasks in dependency order", "what can run in parallel", "detect a scheduling cycle" — build systems, CI/CD pipelines, workflow orchestration. If not every task ends up scheduled, there's a cycle.
