## Shape of each problem folder

```
<N>. <Problem_Name>/
├── README.md                       — the original problem writeup: statement, hints,
│                                     official answer, walkthrough, talking points, follow-ups
├── <N>. <Problem_Name>.ipynb       — study notebook: concepts primer, solutions ordered
│                                     naive -> optimal, verification, empirical complexity
│                                     benchmark, patterns learned
└── <name>_explained.md             — the same idea in plain language, with an analogy and a
                                      narrated worked example
```

`bench_utils.py` (the shared benchmarking helper used by every notebook) stays at this folder's root — each notebook finds it by walking up from its own directory, so it works regardless of nesting depth.

## Every notebook runs

All 27 notebooks execute top to bottom with no errors, and every one ends its verification cell with `All assertions passed.` The Java-only reference answers are reimplemented in Python so their claims are actually executed rather than asserted in prose.

To re-run them all:

```bash
python - <<'EOF'
import json, glob, io, os, contextlib
for path in sorted(glob.glob("*/*.ipynb")):
    d = os.path.dirname(path); cwd = os.getcwd(); os.chdir(d)
    g, buf = {"__name__": "__main__"}, io.StringIO()
    try:
        with contextlib.redirect_stdout(buf):
            for c in json.load(open(os.path.basename(path), encoding="utf-8"))["cells"]:
                if c["cell_type"] == "code":
                    exec("".join(c["source"]), g)
        print("OK  ", path)
    except Exception as e:
        print("FAIL", path, e)
    finally:
        os.chdir(cwd)
EOF
```

## ⚠️ Corrections to the official answers

Running the official code surfaced several genuine errors. Each is documented in the relevant problem's README under a "correction" heading, and covered by an assertion in its notebook:

| Problem | Issue |
|---|---|
| [11. Task Scheduler](11.%20Task_Scheduler/README.md) | Claims Python `set` iteration preserves insertion order (it does not), so the output is non-deterministic. Also, a FIFO queue does **not** give "earliest submitted first" — that needs a heap. |
| [12. Linked Hash Map](12.%20Linked_Hash_Map/README.md) | `put` moves an existing key to the tail, which contradicts the answer's own "insertion order" claim and is not Java's default behaviour. |
| [15. Random Dice Roll](15.%20Random_Dice_Roll/README.md) | `isinstance(n, int)` accepts `True`/`False`, because `bool` subclasses `int`. |
| [17. Regex Checking](17.%20Regex_Checking/README.md) | Claims O(n·m) for code with **no memoisation**; it is actually exponential (measured: 1.2 M calls vs 171). |
| [19. Scores Finding](19.%20Scores_Finding/README.md) | Hint 3's `max(best.get(name, 0), score)` erases every negative score. |
| [20. Smallest Numbers](20.%20Smallest_Numbers/README.md) | The problem statement is genuinely ambiguous; the answer silently picks one of two readings. |
| [22. Billing System](22.%20Billing_System/README.md) | Charges the minimum for plans that have not started yet. |
| [24. Hash Map](24.%20Hash_Map/README.md) | `get` returns `-1` for "not found", colliding with a stored `-1`; `_resize` re-enters the public `put`. |
| [25. Hash Table](25.%20Hash_Table/README.md) | Identifies heap entries by timestamp (which can collide) and uses `time.time()` instead of `time.monotonic()`. |
| [26. Integers Squaring](26.%20Integers_Squaring/README.md) | Claims the two-pointer version can run in place with O(1) space. It cannot — the notebook shows the wrong output it produces. |
