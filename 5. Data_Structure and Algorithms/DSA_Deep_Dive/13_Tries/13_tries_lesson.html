Tries (Prefix Trees)

A trie is a tree keyed by characters: each path from the root spells out a string, and words that share a prefix share the same nodes. That single structural fact is why insert, search, and "does anything start with this?" all cost O(word length) — no matter how many words are stored.

Canonical example

words = ["cat", "car", "card", "dog"]

search('car') = True · search('ca') = False · starts_with('ca') = True

Why this matters

Autocomplete / typeahead

Given a few typed letters, walk to that node once, then collect every complete word in the subtree below it — no scanning the whole dictionary.

Spell-checkers

"Is this exact string a real word?" is a single walk plus one flag check, regardless of how large the dictionary is.

IP routing / word games

Routing tables use the same idea for longest-prefix match; Scrabble and Boggle solvers use it to prune branches that can never form a word.

Instructor note: a hash set already answers "is this exact string present?" in O(L). A trie exists for the question a hash set structurally cannot answer without scanning everything: "which words start with this?"

What is a trie?

Simple definition

A trie is a tree where the edges are labeled by characters instead of arbitrary values. Following a path from the root spells out a string, and any two words that start the same way walk the same nodes for as long as they agree.

What each node stores

A node carries almost nothing: a children map from character to child node, and one boolean, is_word. Reaching a node only proves the string-so-far is a prefix of something; the flag is the only thing that says a full word actually ends there.

Beginner shortcut: if two words start with the same letters, they share the same nodes for those letters — the trie only branches at the first character where two words disagree.

Step-by-step thinking process

1

Walk one character at a time

Every operation — insert, search, starts_with — is the same loop: start at the root, move to the child for the next character.

2

Reuse before you create

If a child already exists for this character, step into it. Only create a new node when nothing exists there yet — that's what makes prefixes free.

3

The end of a word is a flag, not a node type

There is no special "leaf" node class. Any node can have is_word = True, whether or not it also has children.

4

Prefix questions just stop the walk early

To check a prefix, walk the characters and stop — you never need to look at is_word at all.

How the input becomes a trie

A trie is built by inserting one word at a time. Each insert either reuses existing nodes or grows exactly the nodes it needs — nothing more.

Input word list

root.children = {'c': node_c, 'd': node_d} node_c.children = {'a': node_ca} node_ca.children = {'t': node_cat (is_word=True), 'r': node_car (is_word=True)} node_car.children = {'d': node_card (is_word=True)} node_d.children = {'o': node_do} node_do.children = {'g': node_dog (is_word=True)}

Insert "cat"

Root has no 'c' child yet, so three brand-new nodes are created: c → a → t. The t node is marked is_word = True.

Insert "car"

c and a already exist and are reused. Only r is new. The r node is marked is_word = True.

Insert "card"

c, a, and r all already exist — the walk lands on the same r node that "car" ends on. Only d is new. That d node is marked is_word = True.

Insert "dog"

Root has no 'd' child, so this starts a completely separate branch: three new nodes d → o → g, with g marked is_word = True.

Critical point: reaching a node only ever proves the string-so-far is a prefix of some word. Whether it is also a complete, stored word is a separate question, answered only by that node's is_word flag. "car" is both a prefix (of "card") and a word — that is normal, not a special case.

Method 1: insert

Walk the word character by character from the root. Reuse a child if it already exists; create it if it doesn't. When the loop finishes, mark whatever node you landed on as a complete word.

class TrieNode: def __init__(self): self.children = {} # char -> TrieNode self.is_word = False # does a word END here? class Trie: def __init__(self): self.root = TrieNode() def insert(self, word): node = self.root for ch in word: # walk/create one node per character if ch not in node.children: node.children[ch] = TrieNode() node = node.children[ch] node.is_word = True # mark the final node as a word end

Key mental model

if ch not in node.children is the entire reason prefixes are shared: a new node is created only the first time a branch is needed, never again for later words that pass through it.

Common insert mistake

Forgetting node.is_word = True after the loop. Every node still gets created correctly, but search() will never find the word — only starts_with() would still find the path.

Why the children dict matters

A dict gives O(1) lookup for "does this character already have a branch here?" — that single check is what makes insert cost O(word length) instead of scanning existing words.

Method 2: search vs starts_with

Both methods call the exact same _walk helper and land on the exact same node for the exact same string. The only difference is the check performed once the walk is over: search also requires is_word to be True; starts_with only requires that the walk didn't fall off the trie.

def search(self, word): node = self._walk(word) return node is not None and node.is_word def starts_with(self, prefix): return self._walk(prefix) is not None def _walk(self, s): node = self.root for ch in s: if ch not in node.children: return None node = node.children[ch] return node

Autocomplete extends the same walk one step further: land on the prefix node, then DFS the subtree below it and collect every node with is_word = True.

def words_with_prefix(trie, prefix): node = trie._walk(prefix) out = [] def dfs(n, path): if n.is_word: out.append(prefix + path) for ch, child in sorted(n.children.items()): # sorted -> alphabetical order dfs(child, path + ch) if node: dfs(node, "") return out # words_with_prefix(trie, "ca") -> ["car", "card", "cat"]

Key mental model

Steps 5-6 and 8-9 above are pixel-for-pixel the same walk. search("ca") and starts_with("ca") land on the exact same node with the exact same is_word = False — only the final check differs.

Common mistake

Writing starts_with to check node.is_word the way search does. That wrongly rejects a real prefix like "ca" just because "ca" was never inserted as its own word.

Why is_word matters

Without the flag, a trie could only ever tell you "this string exists as a path" — it could never distinguish a stored word from a substring of a longer one.

Edge cases you should test

Case A: searching a prefix that was never inserted as a word

trie.search("ca") vs trie.starts_with("ca")

search("ca") = False · starts_with("ca") = True

The walk for "ca" lands on a real node — but that node's is_word is False because "ca" alone was never inserted. search requires the flag; starts_with does not.

Case B: inserting a word that is already a prefix of an existing word

trie.insert("ca") after cat/car/card/dog are already inserted

Zero new nodes created · only node_ca.is_word flips to True

The walk for "ca" reuses the existing c → a nodes and lands on node_ca, which already exists as an internal (non-word) node. The only change is that its is_word flag flips to True — the trie's shape does not change at all.

Case C: the empty string

trie.search("") and trie.starts_with("")

starts_with("") = True always · search("") depends on whether "" was inserted

for ch in "" never executes, so the walk never leaves the root and immediately returns it. node is not None is trivially True — every trie "starts with" the empty string. search("") is only True if root.is_word was explicitly set, which almost never happens.

How to derive this in an interview

Reasoning path

The question is about prefixes — autocomplete, "starts with", spell-check suggestions — not just exact lookup.

A hash set answers exact lookup in O(L), but has no way to enumerate by prefix without scanning every stored string.

I need a structure where matching characters do shared work: branch per character, and let common prefixes reuse the same nodes.

That's a trie: each node is just a children map plus an is_word flag.

insert / search / starts_with are all O(word length), independent of how many words are stored — and prefix listing is a short DFS from wherever the walk stops.

What to say out loud

  • "I'll use a trie because the question is about prefixes, not just exact matches."
  • "Each node only needs two things: a map from character to child node, and a boolean for 'a word ends here.'"
  • "insert walks the word, creating a node only when a character isn't already a child — that's what makes shared prefixes free."
  • "search and starts_with are the same walk; they only disagree on whether the final flag has to be True."

Common beginner coding mistakes

insert mistakes

  • Forgetting node.is_word = True after the loop — the word becomes permanently unsearchable by search(), even though starts_with() would still find it.
  • Creating a new node unconditionally instead of checking if ch not in node.children first — this silently disconnects any word already stored under that branch.
  • Giving every node the same shared children dict by accident instead of a fresh one per node — corrupts every other branch.
  • Assuming inserting "car" after "card" needs a new node — it doesn't; "car" already exists as an internal node, only its flag needs to flip.

search / starts_with mistakes

  • Indexing node.children[ch] directly instead of the safe if ch not in node.children: return None guard, which raises a KeyError instead of failing cleanly.
  • Returning node.is_word from starts_with() instead of node is not None — wrongly returns False for a valid prefix that never happens to be a complete word.
  • Returning node is not None from search() instead of node is not None and node.is_word — wrongly returns True for any string that merely shares a path with a longer word.
  • Assuming a successful walk proves the word was inserted — it only proves the prefix exists.

Practice questions

Try these first in your head. Then open the answer only after you commit to a guess.

Practice 1 — Using the trie built from ["cat","car","card","dog"], what does trie.search("card") return, and what does trie.starts_with("ca") return? Why is the second one True even though "ca" itself was never inserted?

Answer: search("card") = True — "card" was inserted, so its node's is_word flag is True. starts_with("ca") = True because the walk lands on a real node (the shared c → a path); starts_with never checks is_word, so it does not matter that "ca" alone was never inserted as a word.

Practice 2 — If you now call trie.insert("do"), how many brand-new TrieNode objects get created, and what is the one thing that actually changes?

Answer: Zero new nodes. The walk for 'd' then 'o' reuses the existing nodes created while inserting "dog" (root → d → do). The only change is that the do node's is_word flag flips from False to True — "do" becomes a second valid word sharing a path with "dog".

Practice 3 — Calling words_with_prefix(trie, "car"), what list comes back, and why does it include "car" itself and not just "card"?

Answer: ["car", "card"]. The DFS starts at the node reached by walking "car", and at every node it visits — including that very first one — it checks n.is_word before recursing into children. Since the "car" node's own flag is True, it gets appended before the DFS even descends into its 'd' child to find "card".

Final takeaway

A trie is not a new data structure to memorize in the abstract — it is a tree where the alphabet is the branching factor, and every node quietly asks one question: does a word end here? insert grows that tree one character at a time, reusing whatever already exists. search and starts_with are the identical walk; the only thing that changes is whether you check that one flag at the end. Once you can write those three functions from memory, autocomplete, spell-check, and prefix search are the same handful of lines with different endings.
