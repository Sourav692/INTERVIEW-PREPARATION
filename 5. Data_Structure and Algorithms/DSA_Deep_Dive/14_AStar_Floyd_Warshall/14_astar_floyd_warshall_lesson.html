A* Search and Floyd-Warshall Shortest Paths

Dijkstra is the baseline every shortest-path algorithm builds on. This page covers its two most useful relatives: A*, which adds a heuristic so a single-source, single-goal search stops wasting time exploring the wrong direction, and Floyd-Warshall, which throws away the single-source idea entirely and computes the shortest distance between every pair of vertices in one triple loop. Both are traced step by step against the real notebook code, not a simplified re-write.

Canonical example

adj = {0:[(1,1),(2,4)], 1:[(2,1),(3,5)], 2:[(3,1)], 3:[(4,2)], 4:[]}, start = 0, goal = 4

A* finds 0 → 4 = 5 (identical to Dijkstra)

Why this matters

Game pathfinding & maps

An NPC walking to a target tile and a GPS routing you to one address are the same problem: one start, one goal, and a cheap way to estimate remaining distance (straight-line distance on the map). That's exactly what A* is built for.

Small dense all-pairs tables

A flight network's layover-cost table, or any small graph where you'll repeatedly ask "what's the cost from X to Y" for many different X and Y — precompute the whole table once with Floyd-Warshall instead of re-running a single-source search over and over.

Transitive closure & reachability

Swap "min" and "+" for "OR" and "AND" in the same triple loop and Floyd-Warshall answers "can i reach j at all?" for every pair at once — used in dependency graphs, permission systems, and compiler reachability analysis.

Instructor note: both algorithms are Dijkstra's core relaxation idea (if a candidate distance beats the current one, take it) wearing a different hat — A* narrows Dijkstra's search with a heuristic, Floyd-Warshall repeats it for every possible intermediate vertex instead of every possible source.

What are A* and Floyd-Warshall?

A* — Dijkstra with a sense of direction

Dijkstra always expands the node with the smallest cost-so-far, g, so it grows outward equally in every direction. A* instead expands the node with the smallest f = g + h, where h(n) is a heuristic guess of the remaining distance from n to the goal. Nodes that look both cheap-so-far and close-to-the-goal get explored first.

Floyd-Warshall — every pair, one triple loop

Instead of one source, Floyd-Warshall builds an n x n distance matrix and asks, for every pair (i, j) and every possible intermediate vertex k: "is routing i → k → j cheaper than what I already have for i → j?" After trying every k as an intermediate, the matrix holds the true shortest distance between every pair.

Beginner shortcut: if the question says "from here to there" and gives you some way to estimate distance (coordinates, straight-line distance) — reach for A*. If the question says "between every pair" or hands you a small dense weight table — reach for Floyd-Warshall.

Step-by-step thinking process

1

Identify the scope

One source to one specific goal, or the distance between every pair of vertices? That single question decides which algorithm family you're in.

2

One goal + a distance estimate

If you can cheaply estimate "how far is n from the goal" (grid distance, straight-line distance) — that's A*. Priority becomes f = g + h instead of just g.

3

Every pair, or negative edges

If you need all-pairs distances, or the graph has negative edges (but no negative cycle) — that's Floyd-Warshall's triple loop over k, i, j.

4

Sanity-check the tool

For A*, confirm h never overestimates (admissible). For Floyd-Warshall, confirm k is the outermost loop and check the diagonal for negative cycles afterward.

Build A*'s adjacency list

Each directed edge (u, v, w) is appended to adj[u] as the pair (v, w) — one direction only, because this graph is directed.

Attach A*'s heuristic table

A separate lookup h(n) is defined alongside the graph — it never changes during the search, it's just consulted every time a node's priority is computed.

Build Floyd-Warshall's distance matrix

dist[i][j] = 0 on the diagonal (a vertex is zero distance from itself), dist[i][j] = weight where an edge exists, and dist[i][j] = infinity everywhere else — infinity literally means "no path found yet."

Critical point: A*'s heuristic is external information you supply about the goal; Floyd-Warshall's matrix has no concept of a goal at all — it improves every cell simultaneously as more intermediate vertices become available.

Method 1: A* search

A* is Dijkstra with one change: the priority queue is ordered by f = g + h instead of just g. g is the real cost so far (exactly Dijkstra's dist); h is a guess of what's left. As long as h never overestimates, sorting by f still guarantees the goal is reached optimally — it just gets there having explored far fewer irrelevant nodes.

import heapq def a_star(adj, start, goal, h): g = {start: 0} pq = [(h(start), start)] # ordered by f = g + h while pq: _f, u = heapq.heappop(pq) if u == goal: return g[u] # reached the goal, cheapest-first for v, w in adj[u]: ng = g[u] + w # actual cost to v through u if ng < g.get(v, float("inf")): g[v] = ng heapq.heappush(pq, (ng + h(v), v)) # priority uses the heuristic return float("inf")

Key mental model

f = g + h means "the best total cost through this node, if the heuristic's guess is right." Sorting the heap by f instead of g is the entire difference from Dijkstra — it biases exploration toward the goal instead of outward in every direction.

Common A* mistake

Popping by g instead of f = g + h. That silently turns A* back into Dijkstra with extra bookkeeping — the heuristic never gets a chance to steer the search.

Why stale heap entries are fine

Notice (6,2) and (7,3) stay in the heap unprocessed at the end. That's cheaper than searching the heap to remove outdated entries — the next pop for that node would just find a worse-or-equal g and skip it (or, as here, the algorithm returns before ever reaching them).

Method 2: Floyd-Warshall

Floyd-Warshall asks the same relaxation question Dijkstra asks — "does routing through some vertex beat what I already have?" — but for every pair (i, j), trying every vertex k as the allowed intermediate stop, one k at a time. The trick is entirely in the loop order: k must be outermost.

def floyd_warshall(n, weight): """weight[i][j] = edge cost (INF if none, 0 on the diagonal).""" INF = float("inf") dist = [row[:] for row in weight] # copy initial edge weights for k in range(n): # allow k as an intermediate... for i in range(n): # ...for every pair (i, j) for j in range(n): if dist[i][k] + dist[k][j] < dist[i][j]: dist[i][j] = dist[i][k] + dist[k][j] return dist

Key mental model

By the time the k loop finishes vertex k, dist[i][j] is guaranteed correct for every path that only uses intermediates from 0..k. That invariant only holds if k moves slowest — hence "outermost."

Common Floyd-Warshall mistake

Swapping the loop order (i or j outermost). It still runs, still returns an answer — just occasionally the wrong one, because the DP invariant is gone. This is a silent bug, not a crash.

Why we only traced 3 of 64 comparisons

n=4 means 4x4x4=64 total (k,i,j) triples get checked, but only 3 ever improve dist. Tracing every no-op would be 61 nearly-identical "no update" steps — this page shows the meaningful ones and states plainly where whole rounds produced nothing.

Edge cases you should test

Case A: h(n) = 0 everywhere

a_star(adj, 0, 4, lambda n: 0)

Still returns 5 — but A* degenerates into plain Dijkstra

With no heuristic signal, f = g + h reduces to f = g, which is exactly Dijkstra's ordering. The answer is still correct (a heuristic of 0 is technically admissible — it never overestimates), but the search explores in every direction instead of toward the goal. This is the useful mental check: A* with h=0 IS Dijkstra.

Case B: an inadmissible heuristic returns the WRONG answer

adj = {'A':[('B',1),('C',100)], 'B':[('C',1)], 'C':[]}, h = {'A':0, 'B':200, 'C':0}

A* returns 100 — the true shortest path is 2

The true shortest path is A → B → C, costing 1+1=2. But h(B)=200 wildly overestimates the true remaining distance from B to C (which is only 1). That inflates B's priority to f = g(B)+h(B) = 1+200 = 201, so the direct edge A → C (f = 100+0 = 100) gets popped first, hits the goal, and A* returns immediately with the wrong, more expensive answer. Confirmed by running both versions: with an admissible h = {'A':1,'B':1,'C':0}, A* correctly returns 2. This is exactly why h must never overestimate.

Case C: negative edges are fine; a negative cycle shows as a negative diagonal

0->1 (1), 1->2 (-1), 2->0 (-1) — the cycle sums to 1 + (-1) + (-1) = -1

After Floyd-Warshall: dist[0][0]=-1, dist[1][1]=-1, dist[2][2]=-2

Floyd-Warshall handles individual negative edges without any special casing — the recurrence dist[i][j] = min(dist[i][j], dist[i][k]+dist[k][j]) doesn't care about sign. But when a cycle's total weight is negative, a vertex can "cheapen a path back to itself" indefinitely. That shows up as dist[i][i] < 0 on the diagonal after the algorithm finishes — check any(dist[i][i] < 0 for i in range(n)) to detect it. (Confirmed by running the notebook's own example: diagonal = [-1, -1, -2], negative cycle? True.)

All four are the same relaxation idea at different scopes. For all-pairs on a large, sparse, non-negative graph, V calls to Dijkstra (O(V·(V+E) log V)) usually beats Floyd-Warshall's flat O(V³), since E << V². Floyd-Warshall wins when the graph is small/dense, has negative edges, or when the triple loop's simplicity is worth more than shaving constants.

How to derive this in an interview

Reasoning path

"Do I need one path to one specific goal, or distances between every pair?"

One goal, and I can cheaply estimate remaining distance (coordinates, grid distance) → A*.

One goal, no good estimate available → plain Dijkstra (equivalent to A* with h=0).

Every pair, small/dense graph, or negative edges possible → Floyd-Warshall.

Every pair, large/sparse graph, no negative edges → V calls to Dijkstra is usually cheaper than O(V³).

What to say out loud

  • "Dijkstra explores equally in every direction; if I only care about one destination and can estimate how far away it is, I can bias the search toward it with A* by sorting on f = g + h instead of g."
  • "The heuristic has to never overestimate the true remaining distance, or A* can lock in a path that only looked cheapest — that's why admissibility is the one non-negotiable property."
  • "If I need distances between every pair, not just one, and the graph is small enough, Floyd-Warshall's triple loop does it in one pass and handles negative edges for free."
  • "The correctness of Floyd-Warshall depends entirely on k being the outermost loop — that's what lets each round of k assume everything found with smaller intermediates is already final."

Common beginner coding mistakes

A* mistakes

  • Popping by g instead of f = g + h — quietly turns A* into Dijkstra.
  • Using an inadmissible heuristic that overestimates — can return a wrong, suboptimal path without any error or warning.
  • Checking u == goal at push time instead of pop time — a node can be pushed multiple times with different g values before the best one is ever popped.
  • Forgetting that "no path exists" just means the loop drains and falls through to return float("inf") — make sure that path is actually reachable in your test.

Floyd-Warshall mistakes

  • Looping i or j outermost instead of k — breaks the DP invariant silently; the code still runs and still returns numbers.
  • Forgetting to initialize the diagonal to 0 — without dist[i][i] = 0, a vertex can look unreachable from itself.
  • Assuming Floyd-Warshall detects negative cycles automatically — it doesn't error or hang, it just silently produces a corrupted answer; you must explicitly check the diagonal afterward.
  • Reaching for Floyd-Warshall on a huge sparse graph — O(V³) will badly lose to V rounds of Dijkstra there.

Practice questions

Try these first in your head. Then open the answer only after you commit to a guess.

Practice 1 — Given adj = {0:[(1,2)], 1:[(2,2)], 2:[]} and h = {0:4, 1:2, 2:0}, trace A* from 0 to 2 by hand. What does it return, and is h admissible?

Answer: 4. g={0:0}, pop 0 (f=4), relax 1: g[1]=2, push f=2+2=4. Pop 1 (f=4), relax 2: g[2]=4, push f=4+0=4. Pop 2 (f=4) — goal, return g[2]=4. h is admissible: the true remaining distance from 0 is 4 (matches h(0)=4 exactly), from 1 is 2 (matches h(1)=2), from 2 is 0. Since it never exceeds the true remaining distance (here it's exactly equal — a "perfect" heuristic), it is admissible. Verified by running the real code.

Practice 2 — Run Floyd-Warshall on 2 vertices with one directed edge 0 -> 1 (weight 5) and no edge 1 -> 0. What is dist[1][0] after it finishes?

Answer: still infinity. Floyd-Warshall only finds a path if one actually exists somewhere in the graph — it never invents a reverse edge. With dist = [[0,5],[INF,0]], no choice of intermediate k can ever produce a route from vertex 1 back to vertex 0, so dist[1][0] stays INF. Verified by running the real code.

Practice 3 — An interviewer gives you Manhattan distance as the heuristic for grid pathfinding, but the character can move diagonally at the same cost as a horizontal/vertical step. Is Manhattan distance still admissible?

Answer: No. Manhattan distance sums horizontal and vertical distance separately (e.g. 3 right + 3 up = 6 "moves"), but a mover who can also step diagonally could cover the same displacement in only 3 moves. Manhattan distance therefore overestimates the true remaining cost whenever diagonal movement is allowed, which violates admissibility — A* can then return a suboptimal path, the same failure mode as the inadmissible-heuristic edge case above. The fix is Chebyshev distance (max(dx, dy)) or octile distance, both of which correctly account for diagonal movement.

Final takeaway

Both algorithms are the same relaxation idea Dijkstra introduced, aimed at a different scope. A* narrows the search by sorting on f = g + h instead of g alone — correct as long as h never overestimates. Floyd-Warshall widens the search by trying every vertex as a possible intermediate stop for every pair, one k at a time — correct only because k is the outermost loop. Pick by scope: one goal with a usable estimate reaches for A*; every pair (especially with negative edges) reaches for Floyd-Warshall.
