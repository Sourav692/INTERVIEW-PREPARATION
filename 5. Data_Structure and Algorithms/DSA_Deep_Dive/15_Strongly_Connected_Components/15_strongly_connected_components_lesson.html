Strongly Connected Components in a Directed Graph

An SCC is a maximal group of vertices where every one can reach every other one — forward, along the arrows. This page traces the two standard ways to find them, Kosaraju (two DFS passes over a reversed graph) and Tarjan (one DFS with discovery/low-link numbers), against one real, verified graph, so you can watch exactly what each algorithm's state looks like on every single step.

Why this matters

Deadlock & dependency cycles

A "depends on" graph where module A depends on B and B depends back on A is a deadlock waiting to happen. Any SCC of size > 1 in a dependency graph is exactly that knot — vertices that must be resolved together, not one at a time.

2-SAT

2-SAT builds an implication graph from every clause. The formula is satisfiable if and only if no variable x ends up in the same SCC as its negation ¬x — SCCs turn a satisfiability question into a reachability question.

Condensing a graph into a DAG

Collapse every SCC into one super-node and any directed graph becomes acyclic. That unlocks every algorithm that only works on DAGs: topological sort, longest path, dependency-ordered dynamic programming.

Instructor note: SCCs are rarely the final answer by themselves. They are almost always step one of something bigger — find the SCCs, condense to a DAG, then run a DAG algorithm on the much smaller condensation.

What is a strongly connected component?

Simple definition: mutual reachability

An SCC is a maximal set of vertices where every vertex can reach every other vertex by following directed edges. u and v belong to the same SCC exactly when u can reach v and v can reach u.

How this differs from an undirected component

In an undirected graph, one edge already proves both directions are reachable, so "connected" has only one meaning. Here, 2 → 3 proves nothing about whether 3 can reach 2 — it can't. That's why {0,1,2} and {3,4} are two separate SCCs even though the graph is one piece if you ignore arrow direction (that weaker notion is a "weakly connected component").

Beginner shortcut: if you can trace a path forward from u to v AND a separate path forward from v back to u, they're in the same SCC. If you can only go one way, no matter how tangled the graph looks, they are not.

Step-by-step thinking process

1

Build a directed adjacency list

Read each edge u → v and add v to adj[u] only — never the reverse. That's what makes it directed.

2

Test mutual reachability, not just reachability

You're not asking "can I get there" — that's plain reachability. SCC asks "can I get there and back".

3

Choose one DFS discipline

Kosaraju: DFS, remember finish order, reverse the graph, DFS again in that order. Tarjan: one DFS, tracking disc/low and an explicit stack.

4

Read off each closed component

Kosaraju hands you one SCC per DFS tree in pass two. Tarjan hands you one SCC every time low[u] == disc[u] closes and pops the stack.

Read (0,1), (1,2), (2,0)

Each is added to adj in one direction only. Together they form the 0→1→2→0 cycle that makes {0,1,2} mutually reachable.

Read (2,3)

A one-way link between the two clusters. It proves 2 can reach 3, and nothing about 3 reaching 2.

Read (3,4), (4,3)

Both directions exist between 3 and 4, so they are mutually reachable — a second, separate SCC.

Build radj (Kosaraju only, after pass one)

For every original edge u → v, add u to radj[v]. Unlike an undirected graph, you do not build both lists up front — the reversed list is only built once, when Kosaraju needs it.

Critical point: reversing every edge does not delete any information — it is a lossless transformation. Every SCC of the original graph is still an SCC of the transpose, because "u reaches v and v reaches u" stays true no matter which direction you call "forward".

Method 1: Kosaraju — two DFS passes

Pass one runs a plain DFS and records each vertex's finish order (post-order), not its visit order. Pass two reverses every edge and DFS's the transpose again, popping vertices in decreasing finish order. Each DFS tree that pass two grows is exactly one SCC.

Why reversing works (the part that actually makes it click): reversing does not delete the link between the two components — the transpose above still has an edge 3 → 2. What makes Kosaraju correct is combining the reversal with the finish-time order from pass one. There is a classic DFS lemma: if there's an edge from SCC C1 to SCC C2 in the original graph, then the maximum finish time inside C1 is always greater than the maximum finish time inside C2. Here, {0,1,2} → {3,4}, so {0,1,2}'s latest finish time (node 0, finishing last of all) beats {3,4}'s. Pass two always starts its next DFS tree from the unvisited vertex with the highest remaining finish time — so whichever component it starts in cannot have any unvisited component pointing into it in the transpose (any such component would have had to finish even later, and would already have been visited first). The transpose edge 3 → 2 still exists, but by the time pass two reaches it, node 2 is already claimed — so the DFS just stops there instead of merging the two components.

def kosaraju(n, adj): """Returns a list of SCCs (each a list of vertices).""" seen = [False] * n order = [] def dfs1(u): seen[u] = True for v in adj[u]: if not seen[v]: dfs1(v) order.append(u) # push on FINISH (post-order) for i in range(n): if not seen[i]: dfs1(i) radj = [[] for _ in range(n)] # build the transpose (reverse every edge) for u in range(n): for v in adj[u]: radj[v].append(u) comp = [-1] * n sccs = [] def dfs2(u, bag): comp[u] = len(sccs) bag.append(u) for v in radj[u]: if comp[v] == -1: dfs2(v, bag) for u in reversed(order): # decreasing finish time if comp[u] == -1: bag = [] dfs2(u, bag) sccs.append(bag) # each DFS tree on the transpose = one SCC return sccs

Key mental model

The finish-order stack always puts a "source" component of the condensation DAG on top. Pass two peels off exactly one full SCC per DFS tree, from source to sink.

Common Kosaraju mistake

Pushing a node onto the order stack when it is first visited instead of when it finishes. Only finish order guarantees pass two can't leak between components — visit order does not have that property.

Why the transpose matters

Reversing every edge doesn't erase the link between {0,1,2} and {3,4} — the transpose still has 3 → 2. What blocks the leak is processing nodes in decreasing finish order: by the time pass two reaches 3, node 2 already belongs to a closed SCC, so comp[v] == -1 stops it cold.

Method 2: Tarjan — one DFS with low-link numbers

Tarjan finds every SCC in a single DFS pass using two numbers per vertex: disc[u] (when u was discovered) and low[u] (the earliest discovery index reachable from u's subtree, including one back edge). Vertices are pushed onto an explicit stack as they're entered. The moment low[u] == disc[u], u roots a finished SCC — pop the stack down to u to collect it.

import sys def tarjan(n, adj): disc = [-1] * n; low = [0] * n; on_stack = [False] * n stack = []; sccs = []; counter = [0] def dfs(u): disc[u] = low[u] = counter[0]; counter[0] += 1 stack.append(u); on_stack[u] = True for v in adj[u]: if disc[v] == -1: # tree edge: recurse, then pull up low dfs(v) low[u] = min(low[u], low[v]) elif on_stack[v]: # back edge to a vertex still on the stack low[u] = min(low[u], disc[v]) if low[u] == disc[u]: # u roots an SCC -> pop it off the stack comp = [] while True: w = stack.pop(); on_stack[w] = False comp.append(w) if w == u: break sccs.append(comp) for i in range(n): if disc[i] == -1: dfs(i) return sccs

Key mental model

low[u] answers: "from u's subtree, what's the earliest-discovered vertex I can still reach?" If the answer is u itself, nothing below u can escape past u — u caps the component.

Common Tarjan mistake

Checking disc[v] != -1 instead of on_stack[v] when deciding whether to fold v's value into u's low. A node can be visited but already popped into a finished SCC — pulling its disc value in would wrongly stitch two separate components together.

Why the stack matters

The stack always holds exactly the vertices of "open" SCCs — ones whose root hasn't been found yet. Popping down to u the instant low[u] == disc[u] hands you the whole component in one clean slice, no second pass required.

Method 3: Condensing the graph into a DAG

Kosaraju and Tarjan both end with the same thing: comp[u], an SCC id for every vertex. Condensing means building a brand-new, much smaller graph whose nodes are those SCC ids instead of the original vertices. Walk the same edge list one more time — for every original edge u → v, look up comp[u] and comp[v]. If they match, the edge lives entirely inside one super-node and simply vanishes. If they differ, it becomes an edge between two super-nodes, added once (duplicates are dropped). The single most useful fact about this new graph: it can never contain a cycle.

Why the condensation is always a DAG: suppose it did have a cycle, say C1 → C2 → C1. That would mean some vertex in C1 reaches some vertex in C2, and some vertex in C2 reaches back into C1 — so every vertex in C1 and C2 is mutually reachable through that loop. But mutual reachability is exactly the definition of "same SCC". C1 and C2 would never have been computed as two separate components in the first place. A cycle in the condensation would contradict the very definition of an SCC — so it is structurally impossible, not just empirically rare.

def condense(n, adj, comp, num_comps): """Collapse every SCC into one super-node; return the condensation.""" cond_adj = [set() for _ in range(num_comps)] for u in range(n): for v in adj[u]: cu, cv = comp[u], comp[v] if cu != cv: # crossing edge -> record it (set dedups it) cond_adj[cu].add(cv) # else: cu == cv -> internal edge, vanishes inside the super-node return [sorted(nbrs) for nbrs in cond_adj] def is_dag(num_comps, cond_adj): """DFS cycle check with a recursion-stack color array.""" WHITE, GRAY, BLACK = 0, 1, 2 color = [WHITE] * num_comps def dfs(u): color[u] = GRAY for v in cond_adj[u]: if color[v] == GRAY: return False # back edge -> a cycle exists if color[v] == WHITE and not dfs(v): return False color[u] = BLACK return True return all(color[i] != WHITE or dfs(i) for i in range(num_comps))

Key mental model

Every original edge either lives entirely inside one super-node (internal, dropped) or crosses between two super-nodes (kept, deduplicated). That one pass over the existing edge list is the entire algorithm — no new graph traversal is needed once comp[] is known.

Common mistake

Forgetting to dedupe crossing edges. If two different original edges both cross from the same pair of components (imagine an extra edge 1 → 4 alongside 2 → 3), a plain list would record SCC0 → SCC1 twice, producing a parallel edge. Using a set (as in cond_adj[cu].add(cv)) keeps the condensation simple.

Why this matters

This is the entire reason SCCs get computed in practice. Once collapsed, the condensation is guaranteed acyclic — no matter how tangled the original graph's cycles were — so topological sort, longest/critical path, and dependency-ordered DP all become legal again. 2-SAT is the classic exploit: build the implication graph, collapse it, and read satisfiability straight off SCC membership.

Edge cases you should test

Case A: acyclic graph (a DAG)

n = 4, adj = {0:[1], 1:[2], 2:[3], 3:[]}

SCCs = {0}, {1}, {2}, {3} — four singletons

No cycle means no vertex can reach back to an ancestor, so low[u] == disc[u] for every single vertex in Tarjan, and every dfs1 call in Kosaraju becomes its own DFS tree in pass two. A graph that is already a DAG is its own condensation.

Case B: the whole graph is one cycle

n = 4, adj = {0:[1], 1:[2], 2:[3], 3:[0]}

SCCs = {0, 1, 2, 3} — one component

Every vertex can reach every other by walking around the cycle, so there is exactly one SCC covering the whole graph. In Tarjan, only the vertex that started the cycle (the first one discovered) ever gets low[u] == disc[u] — everyone else's low value gets pulled down to it by the closing back edge.

Case C: a self-loop

n = 3, adj = {0:[0, 1], 1:[2], 2:[]}

SCCs = {0}, {1}, {2} — the self-loop changes nothing

A self-loop on 0 means 0 trivially reaches itself, but that was already true of every vertex — an SCC only needs size > 1 to be interesting. In Tarjan, the self-loop is a back edge to a vertex still on the stack (itself), so low[0] = min(low[0], disc[0]) — no change. In Kosaraju, adj[0] containing 0 is simply skipped by the if not seen[v] check, since 0 is already marked seen the instant dfs1(0) starts.

How to derive this in an interview

Reasoning path

The question mentions cycles, mutual dependency, or "a group that can all reach each other" — this is an SCC problem, not plain reachability.

I need a directed adjacency list built from u → v edges only.

I have two standard tools: Kosaraju (two DFS passes + reversed graph) or Tarjan (one DFS + disc/low + a stack). I'll pick Tarjan for a single pass, or Kosaraju if I want something easier to narrate.

Once I have the SCCs, I can mention the condensation: collapsing each SCC into one node always produces a DAG, useful for whatever the interviewer asks next.

What to say out loud

  • "This graph is directed, so 'connected' has to mean 'reachable both ways' — that's the definition of an SCC."
  • "I'll do Kosaraju: one DFS to get a finish order, reverse every edge, then DFS again popping that order — each tree I get is one SCC."
  • "Or I'll do Tarjan: one DFS carrying a discovery index and a low-link value; the moment low[u] == disc[u], u roots a finished SCC and I pop the stack down to it."
  • "Either way this is O(V+E), and if I need a DAG afterward, I collapse each SCC into a single node."

Common beginner coding mistakes

Kosaraju mistakes

  • Pushing onto the order stack on visit instead of finish — breaks the whole ordering guarantee.
  • Forgetting to build the transpose before pass two, and accidentally rerunning DFS on the original graph.
  • Iterating order instead of reversed(order) in pass two — processes the lowest finish time first, not the highest.
  • Reusing the seen set from pass one as the comp array in pass two — they track different things (visited vs. assigned-to-a-component).

Tarjan mistakes

  • Using disc[v] != -1 instead of on_stack[v] to decide whether to update low[u] — folds in already-closed components.
  • Forgetting to set on_stack[u] = False when popping — leaves stale state that corrupts later low-link comparisons.
  • Updating low[u] with low[v] on a back edge instead of disc[v] — back edges use disc[v]; only tree edges use low[v].
  • Checking low[u] == disc[u] before the full neighbor loop finishes, instead of after.

Practice questions

Try these first in your head. Then open the answer only after you commit to a guess.

Practice 1 — adj = {0: [1], 1: [0], 2: []}, n = 3 — what are the SCCs?

Answer: {0, 1} and {2}. A pair with edges both ways is always one SCC of size 2, and an isolated vertex is always its own SCC of size 1.

Practice 2 — Why does dfs1(u) call order.append(u) AFTER its for-loop over neighbours, not before?

Answer: finish order must record when u is fully done — that is, after everything reachable from u has already finished. Appending before the loop would just record visit order (pre-order), which does not have the property that lets pass two safely reverse the graph and pop without leaking between components.

Practice 3 — In Tarjan, vertex u has low[u] = 2, disc[u] = 2. Its child v (reached by a tree edge) has low[v] = 0. What does dfs(u) do, and what does low[v] = 0 tell you?

Answer: dfs(u) sets low[u] = min(low[u], low[v]) = 0, pulling u's low value down to match its child. low[v] = 0 means something inside v's own subtree found a back edge reaching all the way up to the vertex discovered 0th — so v (and now u, transitively) cannot be an SCC root yet. Whatever eventually has low == disc == 0 will absorb both of them into one component.

Final takeaway

Both algorithms answer the same question — which vertices can reach each other and get back — by exploiting DFS finish order. Kosaraju makes that explicit: two passes, a reversed graph, and the guarantee that decreasing finish order never lets pass two leak between components. Tarjan folds the same idea into one pass with low-link numbers, closing a component the instant low[u] == disc[u]. Pick whichever you can explain without hesitating — in an interview, that matters more than which one is "better".
