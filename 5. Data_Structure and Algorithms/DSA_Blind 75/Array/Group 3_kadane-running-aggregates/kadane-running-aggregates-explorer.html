The core flip

The best subarray ending at index i is either just nums[i] alone, or nums[i] tacked onto the best subarray ending at i-1. That single recurrence — carried in one variable — is Kadane's algorithm: a running sum that resets to zero (well, to the current element) whenever carrying it forward would only hurt.

nums = [-2, 1, -3, 4, -1, 2, 1, -5, 4]

best so far−
Press "Step" to begin. cur = best = nums[0] = −2.
current element best subarray (final)
"Drop the negative prefix": if cur ever goes negative, carrying it into the next element can only drag the sum down — so it's always at least as good to restart fresh at the current element. That's exactly what max(x, cur + x) encodes.

Optimal Solution — Kadane's Algorithm · O(n) time, O(1) space

def max_subarray(nums: list[int]) -> int:
    cur = best = nums[0]        # cur = best sum of a subarray ENDING at this index
    for x in nums[1:]:
        cur = max(x, cur + x)   # extend the previous run, or start fresh at x
        best = max(best, cur)   # track the best run seen anywhere
    return best

One pass, O(1) work per element → O(n) time. Two scalar variables → O(1) space.

The core flip

Same "extend or restart" skeleton as Maximum Subarray — but multiplication doesn't preserve ordering the way addition does. A negative number flips sign: today's most-negative running product can become the largest the instant it's multiplied by another negative. So we must track both a running max and a running min.

cur_min−

Press "Step" to begin. cur_max = cur_min = best = nums[0] = 2.
current element best-product window (final)
Why track the min too? Consider [-2, 3, -4]: after -2, cur_max=-2. After 3, naively you'd think max=3 — but the real winner appears after -4: cur_min (which held -6) times -4 gives 24, the true answer. Only tracking max would have missed it entirely.

Optimal Solution — Track Max & Min · O(n) time, O(1) space

def max_product(nums: list[int]) -> int:
    best = cur_max = cur_min = nums[0]
    for x in nums[1:]:
        # a negative x swaps big <-> small, so consider all three candidates
        cand = (x, cur_max * x, cur_min * x)
        cur_max, cur_min = max(cand), min(cand)
        best = max(best, cur_max)
    return best

One pass, O(1) work per element (constant-size candidate set) → O(n) time. Three scalar variables → O(1) space.

The core flip

Profit for selling on day j is price[j] − (cheapest price on any day before j). So carry the minimum price seen so far as you sweep left to right — at each day you can compute the best possible sell profit in O(1), no need to re-scan every earlier day.

Greedy, and provably safe: for any fixed sell day, the best buy day is simply the cheapest day before it. Since we recompute "cheapest so far" as we go, we never need to look backward — each new price either lowers the buy price or raises the best profit, never needing both checked against history.

Optimal Solution — One-Pass Running Minimum · O(n) time, O(1) space

def max_profit(prices: list[int]) -> int:
    min_price = float("inf")     # cheapest buy price seen so far
    best = 0                     # best profit found so far
    for p in prices:
        min_price = min(min_price, p)   # new cheapest day to buy?
        best = max(best, p - min_price) # best profit if sold today
    return best

One pass, O(1) work per element → O(n) time. Two scalar variables → O(1) space.
