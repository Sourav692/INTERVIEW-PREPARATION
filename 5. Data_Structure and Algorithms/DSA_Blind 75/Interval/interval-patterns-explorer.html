The core flip — sort by start, overlaps become neighbors

Every interval problem starts the same way: sort (usually by start time) so that anything overlapping ends up adjacent. Then a single left-to-right sweep does the rest — here, extend the last kept block's end whenever the next interval overlaps it, otherwise start a new block.

[[1,3],[2,6],[8,10],[15,18]]
Press "Step" to begin. Sorted by start: [[1,3],[2,6],[8,10],[15,18]].
Why start <= merged[-1][1], not <: touching intervals like [1,4] and [4,5] should merge into [1,5] — using strict < would leave them separate, which is usually wrong unless the problem explicitly treats touching as non-overlapping.

Optimal Solution — Sort + Sweep · O(n log n) time, O(n) space

def merge_intervals(intervals):
    intervals.sort(key=lambda x: x[0])       # sort by start -> overlaps become adjacent
    merged = []
    for start, end in intervals:
        if merged and start <= merged[-1][1]:  # overlaps the current block
            merged[-1][1] = max(merged[-1][1], end)   # extend its end
        else:
            merged.append([start, end])        # no overlap -> new block
    return merged

Sort dominates → O(n log n) time. Output holds up to n intervals → O(n) space.

The core flip — three phases: before, overlapping, after

The list is already sorted and non-overlapping, so no full sort is needed — just three phases in one pass: copy intervals ending before the new one starts, widen the new interval to swallow everything that overlaps it, then copy whatever's left.

[[1,2],[3,5],[6,7],[8,10],[12,16]], new=[4,8]
Press "Step" to begin. Phase 1: copy intervals ending before new[0]=4.
Why this stays O(n), not O(n log n): the input is guaranteed already sorted — no sort step needed, just a single linear sweep across the three phases.

Optimal Solution — Three-Phase Scan · O(n) time, O(n) space

def insert_interval(intervals, new):
    res = []
    i, n = 0, len(intervals)
    while i < n and intervals[i][1] < new[0]:    # phase 1: entirely BEFORE new
        res.append(intervals[i]); i += 1
    while i < n and intervals[i][0] <= new[1]:   # phase 2: OVERLAPS new -> merge
        new = [min(new[0], intervals[i][0]), max(new[1], intervals[i][1])]
        i += 1
    res.append(new)
    while i < n:                                  # phase 3: everything AFTER
        res.append(intervals[i]); i += 1
    return res

Already sorted, one pass, three phases → O(n) time. Output array → O(n) space.

The core flip — after sorting, conflicts are always adjacent

One person can attend every meeting only if none overlap. After sorting by start time, if two meetings conflict, they must be consecutive in the sorted order — so a single pass checking each meeting against the previous one is sufficient.

[[0,30],[5,10],[15,20]]
Press "Step" to begin. Sorted by start: [[0,30],[5,10],[15,20]].
Why only checking adjacent pairs is enough: once sorted by start, if meeting i doesn't overlap meeting i-1, it can't possibly overlap anything even earlier either — their start times are even smaller and their intervals already ended before i-1's did (in the non-overlap case). The check only needs to look one step back.

Optimal Solution — Sort + Adjacent Check · O(n log n) time, O(1) space

def can_attend_meetings(intervals):
    intervals.sort(key=lambda x: x[0])
    for i in range(1, len(intervals)):
        if intervals[i][0] < intervals[i - 1][1]:   # starts before previous ends
            return False                             # -> overlap
    return True

Sort dominates → O(n log n) time. No extra structures → O(1) space.

The core flip — rooms needed = peak concurrency

The minimum rooms required equals the maximum number of meetings overlapping at any single instant. A min-heap of end times tracks rooms currently in use: when the earliest-ending meeting is already over by the time a new one starts, reuse that room instead of allocating a new one.

Why the heap's smallest end time matters: the earliest-ending meeting is the only candidate room that could possibly be free by the time the next meeting starts — checking any other end time first would be wasted work, since a min-heap always surfaces the smallest in O(log n).

Optimal Solution — Min-Heap of End Times · O(n log n) time, O(n) space

import heapq

def min_meeting_rooms(intervals):
    if not intervals:
        return 0
    intervals.sort(key=lambda x: x[0])
    heap = []                          # end times of meetings currently using a room
    for start, end in intervals:
        if heap and heap[0] <= start:  # earliest-ending meeting is already over
            heapq.heappop(heap)        # -> reuse that room
        heapq.heappush(heap, end)      # this meeting occupies a room until `end`
    return len(heap)                   # rooms in use at the peak

Sort + n heap operations (each O(log n)) → O(n log n) time. Heap holds up to n end times → O(n) space.

The core flip — greedy by earliest finish time

To remove the fewest intervals, keep as many as possible. Sort by end time (not start!) and always keep the interval that finishes earliest — it leaves the most room for everything after it. This is the classic "activity selection" greedy, provably optimal.

Press "Step" to begin. Sorted by END time: [[1,2],[2,3],[1,3],[3,4]].
Why sort by end, not start: sorting by start would let a long early-starting interval block the greedy choice unfairly. Sorting by end guarantees the greedy always considers the interval that frees up the timeline soonest — the key insight that makes this greedy provably optimal (an exchange-argument proof, common to interval scheduling).

Optimal Solution — Greedy by End Time · O(n log n) time, O(1) space

def erase_overlap_intervals(intervals):
    intervals.sort(key=lambda x: x[1])   # sort by EARLIEST finish time
    removed = 0
    prev_end = float("-inf")
    for start, end in intervals:
        if start >= prev_end:            # doesn't overlap the last kept one
            prev_end = end               # keep it
        else:
            removed += 1                 # overlaps -> must remove this one
    return removed

Sort dominates → O(n log n) time. Only a counter and boundary tracked → O(1) space.
