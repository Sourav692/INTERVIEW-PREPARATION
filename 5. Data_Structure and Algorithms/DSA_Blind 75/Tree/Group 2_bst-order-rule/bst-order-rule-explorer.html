The core flip

A BST isn't just "bigger than my left child, smaller than my right child" — every node must fit within a range set by ALL its ancestors, not just its immediate parent. Pass a tightening (low, high) window down the recursion: going left tightens the upper bound to the current value; going right tightens the lower bound.

tree = [5, 1, 4, null, null, 3, 6]
Press "Step" to begin. Checking root (5): range (−∞, ∞).
currently checking passed its range check violates its range → invalid!
Why this example is a classic trap: node 4 is bigger than its direct parent's left-child rule would suggest is fine (it's less than 5) — but 4 sits in 5's left subtree, which the BST rule requires to be entirely < 5 and, once you're inside node 1's right subtree, entirely > 1. So 4 needs to satisfy 1 < 4 < 5 — which it does. The real violation here is elsewhere in the ancestor chain; only carrying bounds down catches it, a single parent-check would miss it.

Optimal Solution — Range Bounds Recursion · O(n) time, O(h) space

def is_valid_bst(root):
    def valid(node, low, high):
        if not node:
            return True
        if not (low < node.val < high):
            return False
        return valid(node.left, low, node.val) and valid(node.right, node.val, high)
    return valid(root, float("-inf"), float("inf"))

Every node checked once → O(n) time. Recursion depth = tree height → O(h) space. (Alternative: in-order walk must be strictly increasing — same complexity.)

The core flip

An in-order walk of a BST visits values in sorted order — that's the single fact this whole problem hinges on. So the k-th smallest value is simply the k-th value the in-order walk emits. Count visits and stop the instant you hit k — no need to walk the rest of the tree.

Why early-stopping beats collecting everything: collecting the full in-order list costs O(n) time and space regardless of k. Stopping the moment count == k costs only O(h + k) — for a small k on a large balanced tree, that's a dramatic saving over walking the whole structure.

Optimal Solution — Early-Stop In-Order · O(h + k) time, O(h) space

def kth_smallest(root, k):
    stack, node, count = [], root, 0
    while stack or node:
        while node:                  # dive to the smallest unvisited node
            stack.append(node)
            node = node.left
        node = stack.pop()
        count += 1
        if count == k:
            return node.val          # found it — stop immediately
        node = node.right
    return -1

Only descends as far as needed to find the k-th value → O(h + k) time, not O(n). Explicit stack depth bounded by tree height → O(h) space.

The core flip

The LCA is the first node where the two targets diverge — one goes left, one goes right (or one equals the current node). The BST ordering tells you exactly which direction to walk at every step, so you never explore a branch that can't contain the answer. That's what makes this O(h) instead of O(n) — dramatically simpler than the general (non-BST) tree version.

tree = [6,2,8,0,4,7,9], p=2, q=8

Why this is much simpler than general-tree LCA: in a plain binary tree (no ordering), finding the LCA requires searching both subtrees for each target and combining results — O(n) with no shortcuts. The BST's ordering removes all that ambiguity: comparing values against the current node tells you definitively which single direction to go.

Optimal Solution — Walk Using BST Ordering · O(h) time, O(1) space (iterative)

def lowest_common_ancestor(root, p, q):
    node = root
    while node:
        if p < node.val and q < node.val:
            node = node.left           # both smaller -> LCA is further left
        elif p > node.val and q > node.val:
            node = node.right          # both larger -> LCA is further right
        else:
            return node.val            # split point (or a match) -> this IS the LCA
    return -1

Walks down at most one path to the split point → O(h) time. Iterative version needs no extra structures → O(1) space (recursive version is O(h) for the call stack).
