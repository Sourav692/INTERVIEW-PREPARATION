What is a connected component?

Simple definition

A connected component is one full cluster of nodes where every node can reach every other node in that cluster.

What you are counting

You are not counting edges. You are counting how many separate islands remain after all valid connections are considered.

Beginner shortcut: if the graph breaks into two separate islands, the answer is 2. If all nodes are reachable from one another, the answer is 1.

Step-by-step thinking process

1

Start with all nodes

Look at every node from 0 to n-1, even if some nodes never appear in the edge list.

2

Read each edge

Every edge says that two nodes should belong to the same component.

3

Merge or explore

Union-Find merges components. DFS explores one full component at a time.

4

Count groups

Whatever number of separate groups remains at the end is the final answer.

How the input becomes a graph

This is where many beginners get stuck. Before DFS starts, convert the edge list into an adjacency list.

Input edges

edges = [[0,1],[1,2],[3,4]]
→

Adjacency list

0: [1] 1: [0, 2] 2: [1] 3: [4] 4: [3]

Read edge (0,1)

Add 1 to node 0's list, and add 0 to node 1's list.

Read edge (1,2)

Add 2 to node 1's list, and add 1 to node 2's list.

Read edge (3,4)

Add 4 to node 3's list, and add 3 to node 4's list.

Critical point: because the graph is undirected, every edge must be added in both directions.

Method 1: DFS traversal

Build the adjacency list. Then scan every node. Whenever a node is unseen, start DFS from it. That fresh start means you found a new component.

from collections import defaultdict def count_components_dfs(n, edges): graph = defaultdict(list) for a, b in edges: graph[a].append(b) graph[b].append(a) seen = set() count = 0 for i in range(n): if i not in seen: count += 1 stack = [i] while stack: node = stack.pop() if node in seen: continue seen.add(node) for nb in graph[node]: if nb not in seen: stack.append(nb) return count

Key mental model

Every time the outer loop finds an unseen node, that means a brand-new component has been found.

Common DFS mistake

Do not forget isolated nodes. That is why the loop must still check every node from 0 to n-1.

Why stack matters

The stack shows which node DFS will process next. Watching it change helps you see the traversal happen.

Method 2: Union-Find

Start with every node in its own group. When an edge joins two different groups, merge them and reduce the component count by one.

def count_components_uf(n, edges): parent = list(range(n)) count = n def find(x): while parent[x] != x: parent[x] = parent[parent[x]] x = parent[x] return x for a, b in edges: ra, rb = find(a), find(b) if ra != rb: parent[ra] = rb count -= 1 return count

Key mental model

count starts at n. It only goes down when two different groups become one.

Common Union-Find mistake

Do not decrement the count for every edge. Only decrement when ra != rb.

Why roots matter

You compare roots, not the original nodes. Different nodes can already belong to the same component.

Edge cases you should test

Case A: no edges

n = 4, edges = []

Answer = 4

Each node is isolated, so each node is its own component.

Case B: fully connected chain

n = 5, edges = [[0,1],[1,2],[2,3],[3,4]]

Answer = 1

All nodes are reachable through the chain, so there is only one component.

Case C: mixed connected + isolated

n = 6, edges = [[0,1],[2,3]]

Answer = 4

Components are {0,1}, {2,3}, {4}, and {5}.

DFS vs BFS vs Union-Find

Method Best beginner takeaway Main structure
DFSExplore one full component deeplyStack or recursion
BFSExplore one full component level by levelQueue
Union-FindMerge groups efficientlyParent list / disjoint set

All three methods rely on the same core truth: once nodes are connected, they belong to the same component.

How to derive this in an interview

Reasoning path

We need the number of separate groups.

A graph may be disconnected.

So we can either explore each unseen part once or keep merging connected nodes.

That gives DFS/BFS or Union-Find.

What to say out loud

  • “I need to count disconnected groups.”
  • “Traversal works because one DFS/BFS covers exactly one component.”
  • “Union-Find works because each successful merge reduces the number of groups by one.”

Common beginner coding mistakes

DFS mistakes

  • Forgetting to build the graph both ways for an undirected graph.
  • Forgetting to loop through all nodes.
  • Missing isolated nodes.
  • Handling visited checks inconsistently.

Union-Find mistakes

  • Decrementing count for every edge.
  • Comparing nodes instead of comparing roots.
  • Forgetting to call find() before union.
  • Thinking parent directly lists final components.

Final takeaway

The real question is simple: how many separate islands of nodes exist? DFS solves it by exploring each island once. Union-Find solves it by merging islands. Same goal, different machinery.
