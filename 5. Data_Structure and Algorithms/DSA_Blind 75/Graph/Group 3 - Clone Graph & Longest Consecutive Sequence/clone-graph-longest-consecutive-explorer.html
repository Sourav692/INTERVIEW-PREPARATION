Clone Graph & Longest Consecutive Sequence

Two more graph-adjacent patterns: traversal with a memo map, and set-based chain building
Clone Graph
Longest Consecutive Sequence

The core flip

To deep-copy a graph, you must copy every node exactly once and rewire the copies to each other — never to the originals. A hash map original → copy makes this simple: the first time you meet a node, create its copy and store it immediately (before recursing into neighbors) — that's what lets the algorithm survive cycles without looping forever.

Why the copy must be created BEFORE recursing into neighbors: in a cycle (1→2→...→1), node 1's neighbor-copying recursion eventually reaches node 1 again. If node 1's copy weren't already in the map at that point, the DFS would recurse into it forever. Creating and storing the copy first means the second visit finds it already there and simply reuses it.

Optimal Solution — DFS with a Clone Map · O(V+E) time, O(V) space

def clone_graph(node):
    if not node:
        return None
    old_to_new = {}                    # original node -> its freshly-made copy
    def dfs(n):
        if n in old_to_new:
            return old_to_new[n]       # already copied -> reuse (breaks cycles!)
        copy = Node(n.val)
        old_to_new[n] = copy           # store BEFORE recursing into neighbors
        for nb in n.neighbors:
            copy.neighbors.append(dfs(nb))   # link copy -> copy, never copy -> original
        return copy
    return dfs(node)

Every node and edge visited once → O(V+E) time. Clone map holds one entry per node → O(V) space. (BFS with a queue is an equally valid O(V+E) alternative.)

The core flip

Numbers that follow each other form a chain. Put everything in a hash set for O(1) membership, then only start counting a run at a true starting point — a number whose predecessor (x-1) is absent from the set. From there, walk upward while the next number exists. Skipping non-starts is what keeps the whole thing linear instead of quadratic.

Why this is still O(n) despite the nested while loop: the outer loop only does real work (the inner while) when x is a true run start — every other number gets skipped in O(1). Across the entire run of the algorithm, each number is visited by the inner while loop at most once (as part of counting its one run), so total work stays linear.

Optimal Solution — Hash Set, Grow From True Starts · O(n) time, O(n) space

def longest_consecutive(nums):
    numset = set(nums)          # O(1) membership tests
    best = 0
    for x in numset:
        if x - 1 not in numset:      # x is the START of a run (nothing comes before it)
            length = 1
            while x + length in numset:   # walk forward while the chain continues
                length += 1
            best = max(best, length)
    return best

Each number is touched by the inner while loop at most once overall (only from its run's true start) → O(n) time despite the nested loop. Set storage → O(n) space.
