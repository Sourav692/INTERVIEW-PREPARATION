🧩 String Patterns — Interview Cheat Sheet

Ten problems, but only a handful of ideas. Learn to spot which one a question is asking for.

🧮 Count the Letters (Frequency Map)

Like tallying votes — you don’t care about order, just how many of each.

The tell (how to spot it): You’re comparing or grouping words by which letters they use, not their order.

How it works: Count each letter into a map. Two words match if their counts match; group words by their count fingerprint. Turns ‘are these the same set of letters?’ into a quick compare.

Problems here that use it: Valid Anagram Group Anagrams

Say this in the interview:
“I’ll count the letters into a map and compare the counts — that’s linear, no sorting needed.”

🧺 Stack for Nesting

A pile of plates — the last one you put down is the first you pick up.

The tell (how to spot it): The most recent thing opened must be the first to close (brackets, nesting, undo).

How it works: Push each opener onto a stack; when a closer arrives, it must match the top — pop it. Empty stack at the end means valid.

Problems here that use it: Valid Parentheses

Say this in the interview:
“The latest opener must close first, so I’ll use a stack — push openers, match and pop on closers.”

👉👈 Two Fingers From Both Ends

Read a word from both ends toward the middle at once.

The tell (how to spot it): You compare mirror positions, or want O(1) memory on a string.

How it works: One index at each end, stepping inward, skipping what doesn’t count and comparing the rest.

Problems here that use it: Valid Palindrome

Say this in the interview:
“Since it’s about reading the same both ways, I’ll use two pointers from the ends — linear time, constant memory.”

🪟 Sliding Window

A stretchy highlighter that grows and shrinks over the text.

The tell (how to spot it): You want the longest or shortest stretch that satisfies a rule (no repeats, at most k changes, contains all of ...).

How it works: Grow the window on the right; when the rule breaks, shrink from the left. Keep a running summary (a set or counts) so you never re-scan.

Problems here that use it: Longest Substring Without Repeating Longest Repeating Character Replacement Minimum Window Substring

Say this in the interview:
“This is a longest/shortest-substring-with-a-rule problem, so I’ll slide a window and keep counts — that’s linear.”

↔️ Expand Around Center

Pin the middle of a mirror and open outward evenly.

The tell (how to spot it): The problem is about palindromes (finding or counting symmetric pieces).

How it works: Try each center (each letter and each gap), stretch outward while both sides match, and record or count what you find.

Problems here that use it: Longest Palindromic Substring Palindromic Substrings

Say this in the interview:
“Palindromes grow from a center, so I’ll expand around each of the ~2n centers — that’s O(n²), no big table needed.”

📏 Length-Prefix Framing

Label a parcel with its size before you tape it shut — the reader knows exactly how much to unwrap.

The tell (how to spot it): You must pack and unpack data safely when it can contain any character.

How it works: Write each chunk’s length before its content. To read back, read the length, then take exactly that many characters — no separator can be confused with data.

Problems here that use it: Encode and Decode Strings

Say this in the interview:
“A plain separator breaks if the data contains it, so I’ll prefix each string with its length and read exactly that many characters.”

Talking through any String problem

1. Restate it simply and try a tiny example by hand (like the animations here).

2. Look for a tell. Comparing letters → count map. Nesting/brackets → stack. Mirror → two pointers. Longest/shortest stretch with a rule → sliding window. Palindromes → expand around center. Pack/unpack → length prefix.

3. Say the brute force first ("check every substring, O(n²)"), then the faster idea and why it’s faster.

4. Mind the edges: empty string, one character, all-same characters, and characters that are punctuation or your own separators.
